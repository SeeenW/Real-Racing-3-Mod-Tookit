# 下一步：轮子 z 轴偏差 / 主动空力旋转过头 —— 原因假设与解决方案

> 写于 2026-10-20 晚。当前状态：`.points` 与 `.banim` 的结构已完全解出，
> 旋转换算已改成 `角度 = 原始值 × 180/32768`（实机验证过 Reventon 刀片 14.996° ≈ 你手动调的 14.888°）。
> 剩下两类偏差：**轮子类锚点的 z**、**空力部件（尤其左右两侧）的旋转量**。

> **2026-10-27 更新（先说结论）**：本文 §1 的"z 偏差是基准问题"判断**正确**，
> 但给出的 `h = 0.2985`（轮胎网格半径）是**错的** —— 全库 463 台车实测，
> `_shared.m3g` 的 `LOD_A_TYRE_mm_tyre` 模板半径几乎恒定 0.2940..0.3024（中位数 0.2990，
> 标准差 0.0015），而每车真实的加载轮胎半径（`carappearances` 外观块 f1/f5）在 0.258..0.364，
> 标准差 0.016 —— **模板网格是统一尺寸，实际大小靠运行时缩放**。
> 正确的 `h` 应当取外观块 f1（前）/ f5（后），见 `points-格式.md` §9。
> 另外还发现 **107 台车的四轮 z 是完全相同的占位值 0.31903 m**（不是实测值），
> 对这些车"四轮均值"恰好没错，对其余 356 台有 6~13 mm 偏差。

## 1. 轮子 / 方向盘：z 轴系统性偏差

### 已知事实
- `.points` 空间：x 右 / y 前 / z 上，**z 以地面为 0**（Reventon 轮心 9.919，除 32 = 0.310 m）。
- 模型空间：原点在**轮心高度**。轮胎网格 `LOD_A_TYRE_mm_tyre` 的局部 bbox 沿竖直方向正好是 ±0.2985，
  所以模型里"地面" = y = **−0.2985**，而不是 −0.309。
- 我们现在用的竖直偏移 `h = 四轮 z 均值 / d`：d=32 时 = **0.3090**，比轮胎半径 0.2985 **大 1.05 cm**。
- x/y 用 d≈31.83 你看着刚好；但轮拱残差拟合（把锚点投到车身顶点，要求车轮点落在轮拱内表面）
  给出最优点 **d = 32.0–32.4**（Reventon 32.20 → 0.015 m；Countach 32.35 → 0.019 m）。

### 解释
z 偏差是**基准（datum）问题**，不是比例问题：比例错了，误差会随坐标线性增长（车顶最明显、轮心几乎为零）；
你说"轮子和方向盘都是 z 差一点"，更像是**一个常数**——正是 `h` 取错造成的 1 cm 级偏差。

### 解决方案（三选一，按可信度排序）
1. **用轮胎半径当基准**：`h = 0.2985`（从 `_shared` 的 TYRE 网格实测，而不是从锚点推）。改动 3 行。
2. **数据拟合 h**：固定 d，令 h 为自由量，最小化"表面锚点（车灯/排气/铰链）到车壳的竖直间隙"的
   中位数。这是纯数据、不需要游戏。
3. **两点反解**：同时拟合 (d, h)，目标函数 = 车轮点到轮拱内表面的距离 + 车灯/排气点到车壳的距离。
   需要至少 6 个可靠锚点；Reventon 有 8 个。

### 验证（明天 5 分钟）
把 `WHEEL_*` 四个空物体 + 轮胎网格一起导入，量"锚点到轮胎轴线"的距离：
理论值应为 0（锚点就是轮心）；实测均值就是 `h` 的误差，方向也一目了然。

## 2. 主动空力：尾翼对、左右两片"转过头"

### 已知事实（Reventon，`_wing.banim` 3 轨 / 1485 ms）

| 轨道 | 部件（去掉 `_mm_*` 后缀） | 局部尺寸 (m) | 旋转（t=0 → t=end） |
|---|---|---|---|
| 0 | `LOD_A_WING_REAR` | 1.00 × 0.08 × 0.34 | 0 → **−15.0°** (X) |
| 1 | `LOD_A_WING_REAR_LEFT` | 0.35 × 0.19 × 0.96 | (8.48, 0, −2.41) → (8.48, **+17.0**, −0.13) |
| 2 | `LOD_A_WING_REAR_RIGHT` | 镜像 | (8.48, 0, +2.41) → (8.48, **−17.0**, +0.13) |

关键事实：
- 左右片不是小端板——0.96 m 长、由 3 个材质子网格组成（`_mm_chassis` / `_mm_ext` / `_mm_misc`），
  是"沿车长的鳍/导流片（也就是你说的主动进气口盖）"。
- 左右片的 **X 旋转两侧相同（+8.48°）**、**Y 旋转镜像（±17°）**：符合"两侧同时抬头 + 向外张开"的对称机构，
  所以配对关系（track1=LEFT, track2=RIGHT）从数据上看是对的，但**不能排除**引擎里是反的。
- 枢轴由 banim 的 ch0..2 给出：(∓0.548, 0.708, 1.160) m —— 这个点在车体内部（y 0.708 高于甲板），
  如果真实铰链在片的前缘，绕它转 17° 会把片"甩"出去，看起来就是转过头。
- `.points` 里**没有任何 WING/PIVOT 记录**（全库 958 个 `.points` 已扫过），所以枢轴只能来自 banim 或几何反解。

### 假设（按可验证性排序）

| 编号 | 假设 | 症状匹配度 | 验证成本 |
|---|---|---|---|
| H1 | 轨道↔左右配对反了 | "转过头/方向不对" | 1 行代码 + 一次渲染 |
| H2 | 旋转用错轴/错顺序（应是 YXZ 或局部轴，而不是世界 XYZ） | "只有尾翼对，两侧不对" | 3 种顺序各渲一张 |
| H3 | **枢轴不对：banim 给的枢轴≈片的几何中心，真正的铰链在片的边缘** | 旋转把片"甩"出去 | 几何反解，半天 |
| H4 | 静止姿态应"叠加"而不是"替换"（网格自带姿态 ≠ 单位矩阵） | 初始就偏，越转越偏 | 渲染对比 |

### H3 为什么最可疑（刚算出来的证据）

刚把 `_wing.banim` 的通道逐个打印了一遍（`analysis\banim_patch.py --dump`）：

```
track 0 (刀片)   ch0 = 0        ch1 = -2.0323 m   ch2 = +0.8541 m   ch3 0 → -15.00°
track 1 (左片)   ch0 = -0.5478 m  ch1 = -1.1604 m  ch2 = +1.0183 m  ch3 +8.48°→+8.48°  ch4 0 → +17.00°
track 2 (右片)   ch0 = +0.5478 m  （ch1/ch2 同左片）                ch3 同上          ch4 0 → -17.00°
```

- 左右片的 ch3（X）相同、ch4（Y）镜像 ⇒ 机构对称（同时抬头 + 向外张开），**配对和符号都合理**。
- 但两个片的局部几何：中心 (−0.096, −0.036, −0.022)、尺寸 (0.351, 0.186, **0.955**) ——
  长轴 0.955 m 就是沿车长方向，而**网格原点几乎就在片的几何中心**。
- 也就是说：现在我们是"绕片的中心转 17°"，片的两端会朝相反方向甩出 ±0.28 m —— 看起来就是"转过头"。
- 刀片则不同：它的局部 bbox 沿车长是 −0.105…+0.234，原点靠近**前缘**（约 1/3 处），
  所以"绕原点转"碰巧接近"绕铰链转"，这也是**为什么只有尾翼看着对**。

### H3 的解法（纯几何，不需要游戏）

1. 把片按 banim 枢轴放到车体上（现在的做法）。
2. 计算片每个顶点到**车身网格**的最近距离，取最近的 5% 顶点 —— 它们就是"贴着车壳"的那条
   **铰链边**。
3. 用这条边拟合一条直线 = 真实铰链轴；把旋转枢轴从"片中心"改到"这条轴上"，角度仍用 banim 的。
4. 判据：旋转后这条边上的点位移应 < 1 mm（现在的做法会位移 0.2 m 以上）。

同一套算法可以顺手验证刀片（应当也落在它的前缘）。

## 5. 边界与风险

- 引擎里 banim 解析函数**静态定位失败**（14 个相关字符串的 xref 全是假阳性：都是 HUD/渲染代码），
  所以"单位/顺序/枢轴"只能靠黑盒探针 + 视觉验证，不能靠读代码。
- 内存扫描（367 MB 可写区）没找到解析后的关键帧，说明引擎做了变换或在别处解码——这条路暂时不划算。
- `.points` 的 z 基准、枢轴选取这两件事**互相独立**，可以分开验证，不必等对方。
