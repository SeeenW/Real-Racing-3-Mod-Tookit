# 下一步：游戏内截帧对照（定位"哪哪都有偏差"）

目标：拿到**游戏真正使用的每件网格的世界变换**，和我们的 `.points` / `.banim` / `.m3g` 推导结果逐件对照，
输出"位置差 / 旋转差 / 缩放比"表格，一次性定位偏差来源（基准 h、枢轴、轴顺序、单位）。

## 工具选择（重要）

| 工具 | 能拿到什么 | 适不适合 |
|---|---|---|
| **Ninja Ripper 2.x** | 抓帧时的**变换前**顶点缓冲 + 贴图 | 只能做几何交叉验证（顶点数 / 包围盒 / 贴图），**没有每件网格的矩阵**，回答不了"哪里偏" |
| **RenderDoc**（推荐） | 每个 draw call 的顶点缓冲 + 顶点着色器常量块（含模型/视图/投影矩阵）+ 纹理 | 支持 OpenGL 与 Vulkan；MuMu 宿主层就是 `mesa_opengl32.dll` / `vulkan-1.dll`，有较大概率能挂上 |

结论：**主工具用 RenderDoc**（免费，renderdoc.org）；Ninja Ripper 若已下载可留作几何交叉验证。

## 你要给我的东西

1. RenderDoc 安装包或便携 zip → 放到
   `D:\rr3\tools\`
   （我负责解压、校验、配好，不动系统盘其它地方）
2. 车库里停好一台有主动空力的车（Countach LPI / Chiron / Reventon 都行），**不要进比赛**
3. 我用 RenderDoc 启动 / 挂上 MuMu 之后，你按 **F12** 抓一帧，告诉我抓到了
4. `.rdc` 文件由我从 RenderDoc 的临时目录（默认 `%TEMP%`）拷到
   `D:\rr3\re\rdc\`

## 我拿到 .rdc 之后做什么

1. 用 RenderDoc Python API 遍历所有 draw call，导出：顶点数、索引数、VB 数据、VS 常量块
2. 以顶点数 + 包围盒为指纹，把 draw call 匹配到 `.m3g` 里的网格名（`LOD_A_WHEEL_mm_wheel` 等）
3. 从常量块里解出模型矩阵（找 4×4、末行 0,0,0,1、平移分量落在合理范围的那块）
4. 对每件部件：
   - 位置差 = 游戏矩阵平移 − 我们的 `pivot`（或轮子锚点）
   - 旋转差 = 游戏矩阵旋转 vs 我们的 Euler（按 180/32768 换算）
   - 缩放比 = 矩阵 3×3 的行范数（验证 1/65536、1/32768 是否有额外系数）
5. 输出 `re\assembly_diff.txt` + 一页结论（哪一项系统性偏、偏多少、改哪个常数）

## 若 RenderDoc 挂不上 MuMu（Vulkan 层被拦）

退回到已有的两条路：
- **黑盒探针**：用 `analysis\banim_patch.py` 改设备副本里 `_wing.banim` 的单通道，进比赛看动作（测完还原，E: 盘不动）
- **照片对照**：游戏内拍照模式固定机位，抓"收起/展开"两张，量像素角度

## 现在的状态

- 身体网格是烘焙在车体空间的（绝对坐标），所以**车身不可能整体偏**；偏差只可能来自
  "被放置的部件"——轮子（`.points` 锚点 + 基准 h）、空力（`_wing.banim` 枢轴 + 旋转）、锚点本身。
- `.points` 除数拟合结果 32.20 / 32.35 / 32.80（三台车），说明不是 π；竖直基准四轮均值 0.309 m
  比轮胎半径 0.2985 m 高 1.05 cm，这是目前唯一的系统性 z 差候选。
- 旋转单位已由实机截图校准为 `原始值 × 180/32768`（Reventon 刀片 14.996° vs 截图 14.888°）。
