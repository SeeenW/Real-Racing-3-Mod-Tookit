# 尾翼发暗：着色器取证与排除记录（2026-10-26 01:00）

## 1. 结论先说

* **尾翼与车身用的是同一个像素着色器**（同一个 Pipeline 17105 / Shader Module 17104，指令序列逐条一致），
  所以**不是**着色器代码、材质 id、法线、UV、顶点色的问题。
* 唯一差别是引擎给这两发 draw **绑定了不同的 LUT 贴图**：
  `set=2, binding=2`（`_23`）与 `set=2, binding=4`（`_26`），都是 1024×1024 RGBA8、swizzle[RGB1] 的
  实时生成的渐变表（RenderDoc 里显示为 2D Color Attachment）。
* ⇒ 问题在**引擎侧的“零件 → 材质集/LUT”选择**，数据侧只有一个自由度：网格名与 81 字节附加块。

## 2. fs 亮暗公式（SPIRV-Cross 产物节选）

```glsl
_88  = clamp(dot(N,V)^2, 0.1, 0.999);
_106 = _34._m3 * texture(_26, vec2(_88,0.0)).xyz;   // 菲涅尔渐变 LUT（binding 4）
_106 *= _56.x;
_120 = dot(texture(_27,_28).xyz, _34._m4);          // 烘焙光照/AO 掩码（binding 5）
_120 = min(1, _120 + _34._m5.z); _120 = _120^4;
_151 = _13 * _120 + _34._m2;                        // 漫反射 + 环境
out  = albedo*_151 + fresnel*2.0*_120 + ...;
```

尾翼「暗红但仍有漆色」= **菲涅尔项丢失（LUT 是暗的那张）+ 漫反射还在**，与公式完全吻合。

## 3. 本轮排除的实验（全部实测）

| 假设 | 操作 | 结果 |
|---|---|---|
| part id 决定 LUT | payload `+38`：尾翼 `0x16` → `0x11`（与车身 `LOD_A_BODY_mm_ext` 的 81 字节块**完全一致**） | 仍暗 ⇒ 不是它 |
| 顶点色是可用开关（B 方案） | `analysis/wing_vcolor.py` 把 `LOD_A_BODY_mm_ext` 15135 个顶点 RGB 全改 `(0,65535,0)` | 车身**仍是红色** ⇒ 顶点色 RGB 没进到输出，**B 方案作废** |

## 6. 2026-10-26 续：材质绑定代码 + 网格已对齐 + appearance 第 36 字节实验

### 6.1 反编译结论：材质是**按 tag** 分配，不是按零件

`FUN_0166866c`（628 B，CarAppearance 的零件绑定）流程：

1. 从 `param_1 + 0x49f8` 取零件槽数组；遍历 m3g 里每个 mesh（`lVar14`）。
2. 对 8 组 LOD（`uVar15` 0..7）× 152 个零件名（`ppuVar13 = &PTR_s_LOD_A_BODY_01fe80d8 + uVar15*0x98`）
   调 `FUN_01668324(meshName, partName, &tagIdx, &damageSuffix, tagTable, 0x15)`。
3. 匹配成功：

   ```c
   pvVar9 = operator_new(0x50);
   FUN_00e1c1c4(pvVar9, lVar14, tagIdx);                          // part[0]=mesh; part[+0xc]=tagIdx
   *(u64 *)(pvVar9 + 0x10) = *(u64 *)(car + tagIdx*8 + 0x3248);   // 材质 = car_material[tagIdx]
   ```

   ⇒ **同一个 tag 的零件拿到同一个材质对象**。车身与尾翼 tag 都是 `ext`，材质必然相同。
4. 一个都没匹配上才打 `Car '%s' contains unreferenced mesh '%s'.`；我们的日志没有这条
   ⇒ 两个尾翼都正常匹配到 `LOD_A_WING_REAR`（LOD_A 子表第 107 项）。

`FUN_01668324`（名字匹配器）：

* `strncmp(meshName, partName, strlen(partName)) == 0` 才算前缀命中；
* 之后可选 `_c<数字>`（损伤等级，写进第 4 个出参）；
* 再要求出现 `_mm_`，并把 `_mm_` 之后的部分拿去和 21 条 tag 表逐个 `strcmp`，
  命中的序号写进第 3 个出参（`ext` = 0）；
* 所以名字形态是 `<零件名>[_cN]_mm_<tag>`，多余的段会被判为不匹配。

## 9. 【2026-10-27 结案】数据侧就能修，不需要改 .so

本文第 1~8 节的**取证全部有效**：尾翼与车身确实是同一个像素着色器，差别只在引擎绑定的
LUT 贴图（`set=2,binding=2` vs `binding=4`）。

但"问题在引擎侧的零件→材质集选择、数据侧只有一个自由度（网格名与 81 字节块）"这个判断
**是错的**：数据侧还有第三个自由度，就在 `liveries/<车>.liveries.bin.nct` 里。

该文件有 **4 张表**（来源 MonkeyTool `docs/FORMATS.md` §"A liveries list"），之前所有工具
只解了第 1 张「贴图表」就停了：

1. 贴图表
2. **网格 → 材质表**（`u32 meshSlot, u32 matSlot`）
3. 第三张表（3×u32）
4. 涂装列表，每条含**材质覆盖表**（`u32 meshSlot, u32 matSlot`）

这两张表就是官方的「零件 → 材质」映射。原厂把 `745 LOD_A_WING_REAR_mm_ext` 映射到
与该涂装 `30 LOD_A_BODY_mm_ext` 相同的漆种材质，尾翼因此跟随车漆。

修法（已落地、已实机验证）：给 611 每个涂装的材质覆盖表插入
`745 -> 同 30`。liveries `4709 → 4749 B`，尾翼现在**和车身同色同光泽**。

详见 `docs/livery槽位表与材质名.md` §2 与 `docs/HANDOFF-20261027.md`。
