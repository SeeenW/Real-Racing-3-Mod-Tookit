# 尾翼动画：我们的 banim vs McLaren P1 原厂 banim

两个文件**结构完全一样**（同一套变体 0 容器：2 条轨道、每轨道 6 通道 × 2 采样率 = 12 条曲线、2172 个关键帧、1980 ms 时长、尾部 trailer 相同），
区别只在写进去的**数值**。因此可以逐通道对比。

## 通道含义（由 make_wing_banim_p1.py 的写入规则反推，已验证）

| 通道 | 含义 | 单位换算 |
| --- | --- | --- |
| c0 | 位置 X | raw / 65536 = 米 |
| c1 | 位置 Y | raw / 65536 = 米 |
| c2 | 位置 Z | raw / 65536 = 米 |
| c3 | 俯仰 X | raw × 180/32768 = 度 |
| c4 | 偏航 Y | 同上 |
| c5 | 横滚 Z | 同上 |

每条通道存两条曲线（2c 用 61 键、2c+1 用 120 键），数值相同，只是采样密度不同。

## 关键差异（轨道 0 = 叶片）

> **2026-10-28 更正**：下面"轨道 0 = 叶片"这个归属**是错的**。
> 后来用网格自带的 keyframe 表（`.m3g` 网格对象尾部 `u32 count` + 每键 14 字节）确认：
> P1 的 `LOD_A_WING_REAR_mm_ext` 有 10 个 key（`_unparsed = 144`），
> `LOD_A_WING_STRUT_REAR_mm_ext` 是空表（`_unparsed = 4`）；而且 keyframe 值与
> **track 1 的 ch3（俯仰）相关 −0.5677**、与 track 0 全部通道相关 ≈ 0。
> ⇒ **track 0 = 支架（`WING_STRUT_REAR`，俯仰恒定 43.36° 不转）、track 1 = 尾翼本体
> （`WING_REAR`，俯仰 21.59° → −19.66°）**。插件原先按名字序配对，正好把两者对调，
> 这就是"尾翼支架绑错了尾翼的动画"的根因。判据与修法见
> `docs/HANDOFF-20261027-4-尾翼轨道与材质.md` §1。
> 下表的通道数值对比仍然有效，只是"轨道 0 属于谁"要按上面这条读。

| 通道 | 我们（当前） | P1 原厂 | 说明 |
| --- | --- | --- | --- |
| pos Y | -1.6650 → -1.5650 m（+0.100） | -1.6405 → -1.9198 m（**-0.279**） | 方向相反：P1 展开时 Y 变小 |
| pos Z | 0.8255 → 1.0654 m（+0.240） | 0.3629 → 0.6586 m（+0.296） | 抬升量已接近 P1 |
| pitch X | 0 → -26°（线性斜坡） | **恒定 43.36°** | P1 叶片是固定攻角，只做平移；我们是让整片旋转 |
| pos X / yaw / roll | 恒定 0 | 恒定 0 | 一致 |

⇒ 两点可疑：①我们把"展开"做成了**整体旋转 26°**，而 P1 是**保持攻角平移**；②Y 方向与 P1 相反。

## 时间曲线形状

- 我们是**严格线性**：61 个键在 1980 ms 内从静止值线性插到展开值（每 33 ms 一个键）。
- P1 的关键帧是**先快后慢**：0 → 495 ms 已走完约 50%，495 ms 之后基本不动（见下方采样表）。所以同样的终点，P1 看起来"弹起来"，我们看起来"慢慢抬"。

## 配套的 _animations.xml（我们的，306 B）

`xml
<?xml version="1.0"?>

<anims>
	<anim name="wing_initial">
		<frames start="0" end="0" />
	</anim>
	<anim name="wing_up">
		<frames start="0" end="30" />
	</anim>
	<anim name="pivot_up">
		<frames start="30" end="60" />
	</anim>
	<anim name="pivot_down">
		<frames start="60" end="30" />
	</anim>
</anims>
`

说明：rames start/end 是 **key 序号**（不是毫秒），wing_up = key 0→30，正好覆盖 2172/12 条曲线中前 31 个键；
pivot_up 30→60、pivot_down 60→30 是给支架/枢轴用的第二段。P1 自己的 xml 是 wing_up 0→75、wing_down 75→0、wing_initial 0→0、wing_race_initial 0→75、pivot_up 80→90、pivot_down 90→80。
