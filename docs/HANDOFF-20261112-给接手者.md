### 1.3 环境坑（踩过，别再踩）

- **`python -X utf8` 必须**。中文路径在 pwsh here-string 里写死会乱码，一律用 `glob.glob(r"E:\DXT*Build260716")[0]` 拿路径。
- **`tempfile.mkdtemp` 在本机建出的目录连 `os.listdir` 都抛 `PermissionError`**（0o700 + ACL）⇒ 一律手建目录。`tools/build_exe.py` 里 `patch_tempfile()` 已把它改成 0o777。
- **`pip install` 全线失败** ⇒ 从 PyPI 下 wheel 用 `zipfile.extractall` 到 `work/pylibs`。
- **`~` / `%APPDATA%` / `%LOCALAPPDATA%` 不可写**，只有 `%TEMP%\dsh-*` 和工作区可写。`rrmod/ui/settings.py` 的 `_path()` 按 `%APPDATA%` → exe 目录 → `%TEMP%` 依次试，源码运行时落在 `<repo>\settings.ini`。
- **改了 `rr3lib/*.py` 之后必须先 `python tools\sync_rr3lib.py`**，否则插件用的是旧副本（`rr3_blender_addon/rr3lib/` 是拷贝，不是链接）。zip 过期 11 天曾经是用户报 bug 的真凶，所以有 `build_addon.py --check`。
- **`tools/build_exe.py` 绝不能 rmtree**。运行中的程序锁 exe 映像与目录本身、不锁其它文件 ⇒ 半删出空壳，报 `Failed to start embedded python interpreter!`。它只 `os.rename` 成 `.old-<stamp>`。
- **每次构建后必须补 `settings.ini` 与 `RR3ModManager_state/`**（从 `.old-*` 拷回），否则 `--check` 报 `540 unknown`。
- 本机 pwsh 偶尔报 `windows-acl-run: --temp is not an existing directory` ⇒ 用 write 工具在该目录建个文件即可恢复。`InvalidOperation: 无法将...绑定到参数"模式"...` 两行 stderr 是纯噪音。

### 2.2 关键格式（一句话版）

| 格式 | 一句话 | 代码 |
| --- | --- | --- |
| `.m3g` | 场景图但**没有节点树**（Group 节点数恒 0），网格顶点直接是坐标；`of_type(14)` 取网格 | `rr3lib/m3g.py` |
| `.banim` | 动画：`u32 magic(0x7F7F7F00)` / 轨道表 / 键表；**位置单位 1/65536 m**、旋转 `π/32768` | `rr3lib/banim.py`、`banim_write.py` |
| `_animations.xml` | 剪辑表：`frames` 是**源动画帧号**，不是 key 序号 | `rr3lib/animxml.py` |
| `.nct` | 加密容器，RC4 两把钥匙（`KEY_NCT` / `KEY_GAMETEXT`） | `rr3lib/nct.py` |
| `.points` | 锚点表，单位 1/32 m，142 个不同锚点名 | `rr3lib/points.py` |
| `.dxt.dds.z` 等四族 | DXT/ETC/ATC 线性、PVRTC 是 gamma 2.2；清单里四行、磁盘只有一行 | `ddsdecode`/`etcdecode`/`pvr` |
| `materials.bin` | `u32 key + u32 len + payload` 记录流，**没有长度前缀**，只能在表尾追加 | `gamematerial.py` |
| spec `<id>_<车>.bin.nct` | 性能/价格/引擎块/升级路线/尾部五字段 | `rr3lib/spec.py` |
| livery 表 | 涂装 → 材质槽 → 贴图槽，三级回退 | `rr3lib/livery.py` |
| 数据记录 `<id>_<车>.bin.nct` | 别名、展示名、**驾驶员姿势字段** | `rr3lib/driver.py` |

### 2.3 三个反直觉的事实（不知道会写出错代码）

1. **`.m3g` 没有节点树**，所以没有"部件的变换"可以清空。工作室导出时把变换烘进了顶点。动画部件的顶点存在**自己原点附近**，游戏按 `pivot + R_track @ vertex` 组装。
2. **尾翼轨道按部件基名字母序配对**，m3g / banim / xml 里都没记录这个映射。52/52 验证过。文件出现顺序**不是**轨道顺序。
3. **`.banim` 的尾块（trailer）不能省**。`u32 n + n×4B`，`n == 轨道数`。没有它引擎会**加载成功然后永不套用**，部件停在原点——看起来像"尾翼消失了"。这个 word 不是任何标准哈希，只能按部件名查表（`rr3_blender_addon/rr3_export.py` 的 `TRAILER_WORDS`）。

## 3. 代码结构

### 3.1 三层

```
rr3lib/          格式层。纯 Python + struct，不 import Qt、不 import bpy。可单独用。
rrmod/           逻辑层（34 模块）。读/写游戏资源、工作副本、清单、打包、部署。
rrmod/ui/        Qt 层（24 模块）。只负责显示与调用逻辑层。
rr3_blender_addon/   Blender 层。自带一份 rr3lib 拷贝（sync_rr3lib.py 同步）。
```

**测试怎么组织的**：`tools/test_rrmod.py` 是一个约 4,700 行的单文件，72 组 `print("NN ...")` 分节，每组一个 `try/except ImportError`。它先 `build_mini()` 造一个**真实子集的迷你安装**（LFA + 表 + 清单 + 动画车 + 生涯 + 42 个画质档 + driver 目录），所有写操作都对着它，**从不碰真安装**。

### 3.2 最重要的一条设计：文件系统当真相，一切编辑先落工作副本

```
<mods 目录>/workspace/<md5(abspath(安装))[:10]>/
    .depot/...        镜像出来的游戏文件（改的就是这里）
    apk/res/...       镜像出来的账本
    pending.json      哪些文件与安装不同（md5 比对）
```

- `rrmod/workspace.py` 的 `capture()` 用 md5 比对工作副本与安装，任何差异都 stage 进 `pending.json`。
- **Deploy 页的 Prepare 只读 `pending.json`**，不读安装。
- 推送时 `deploy.merge_manifests()` **以设备副本为底合并**，只重写本计划推的行，设备有而本地没有的行全部保留。理由：设备清单可能比本地新；曾经因为 37 行幽灵车导致游戏提示"下载"。
- **`Workspace.depot` 是安装的 `.depot`，`Workspace.ws_depot` 才是工作副本的**。这是踩过的坑（材质页读不到自己刚写的行）。

## 4. 不能碰的东西（用户明确拍板的）

1. **`E:` 上的安装是备份，只读。**（用户原话：「e盘上的是备份，你不要写它」）
2. **`materials.bin` 块内的字段不编辑。** 记录流没有长度前缀，错一个字节后面全错位，而游戏不报错、只加载一张"看起来合理"的错表。只能**在表尾追加整块**（`clone_block` + `insert_block`）。
3. **清单只合并不覆盖。** 设备上的清单可能比本地多。
4. **我们推的行写裸态**（`packed == raw`）。压缩器无法复现那 17,029 行的压缩态 md5。
5. **两个闭集不能扩**：aspiration（`Nat/Turbo/Super/None/Electric/Hybrid`）与 layout（`F/M/R/FM`）。引擎块是靠这六个词之一定位的，写个新词会让功率、齿轮数、升级路线对所有 reader 消失。
6. **`pr_max` 不可写**。游戏按基础 PR + 升级路线自算，写了会被覆盖。
7. **不镜像 `driver/` 与大部分 `vehicles/common/`**。没有编辑会写它们，按需回落到安装。
8. **每个 UI 编辑完必须 `_collect()` / `capture()`**，否则文件写了却不进暂存列表（尾翼、涂装、材质、驾驶员四处都踩过）。

### 7.2 加一个新功能的固定套路

1. 逻辑写进 `rrmod/` 的某个模块（纯 Python，抛 `EditError`/`PublishError` 这类明确异常）。
2. 写盘前必须：`editlib._begin("一句人话描述这次编辑")` → `editlib._backup(root, path)` → 写 → `editlib.sync_file(...)`。
3. UI 在 `rrmod/ui/`，改完调 `self.editor.capture(car)` 或 `self._collect()`。
4. 测试加到 `tools/test_rrmod.py` 的**最后一个 `print()` 之前**，新开一组 `print("NN ...")`，用 `check(name, cond, detail)`。
5. `python -X utf8 tools\gen_i18n.py` → 补 `rrmod/data/i18n/zh-Hans.json`（`indent=1` + `sort_keys=True`）→ `i18n.missing("zh-Hans")` 必须为空。
6. 文档三处：`rrmod/README.md`（测试数 + 模块表 + 新节）、`docs/HANDOFF-20261108-资源管理器与待办.md`（新节 3.6.N + 三处数字）、`docs/RRMOD-BACKLOG.md`（`[x]` + 文件末尾 `## Done on YYYY-MM-DD`）。
7. `python tools\sync_rr3lib.py`（如果改了 `rr3lib`）→ `build_addon.py` → `build_exe.py` → **补 `settings.ini` 与 `RR3ModManager_state/`** → `--check` → GUI 存活 20 s。

### 7.3 调试一个"游戏要下载"的 bug

这几乎总是**账本问题**。查这个顺序：

1. 改动过的每个 `.depot/` 路径，`manifestlib.owner_of()` 能不能找到账本？
2. 注册表（`parse_registry`，不是文本模式）里那行的 md5 与磁盘一致吗？
3. 账本里那行的 md5 与磁盘一致吗？
4. 设备上是否有多余文件（比如删了文件但账本没删行，或反过来）？
5. `adb logcat | Select-String "Asset download|Incorrect Asset cache|Assets Update"`。

### 7.4 调试一个"部件不见了/位置不对"

1. `.m3g` 里那个网格在不在？（`M3G(path).of_type(14)`）
2. 顶点是**模型空间**还是**局部空间**？（动画部件必须在局部，`use_world=False`）
3. `.banim` 有尾块吗？（`len(b.trailer_words) == b.num_tracks`）
4. 轨道顺序对不对？（按部件基名字母序）
5. livery 表里有那个部件的材质行吗？（没有就走 `car_flat`，纯黑）
