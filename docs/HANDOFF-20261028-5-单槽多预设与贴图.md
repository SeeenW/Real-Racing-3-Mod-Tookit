## 0. 一句话结论

- **"贴图没进去"不是解码问题**。实测 DDS 解码、图片加载、`Color → Base Color` 连线全都正常；
  真正的问题是**每个涂装占一个材质槽**——Blender 按 polygon 选材质，6 个槽里只指一个，
  用户看到的往往不是默认涂装；另外解码结果落在 `%TEMP%`，重启后被清空 → 全变粉色。
- 现在**每个网格只有一个材质槽**，涂装活在这个材质的**预设**里：每个预设一套
  `bsdf_<n>` + `atlas_<n>` + 两条色带，**只有当前预设的 BSDF 连到 Material Output**，
  `rr3.switch_paint` 只重接这一根线。贴图全部 `pack()` 进 .blend。
- 新增 `rr3lib/ddsdecode.py`（DXT1/3/5 解码）与 `rr3lib/texport.py`（6 种私有容器），
  配 *Textures ▸ Export textures* / *Load car textures* 两个 operator。

## 1. 取证：贴图为什么"看起来没进去"

Blender 4.5 headless，`2014_mclaren_p1`，`materials="game", paint=0`：

| 检查项 | 结果 |
|---|---|
| 网格材质槽数 | **6**（`rr3_paint_slots 6`），每个涂装一个 |
| 节点树 | `Principled BSDF` + `Material Output` + `TEX_IMAGE game_atlas` + `FRAME game_ramps` + `ramp_fresnel` + `ramp_specular` |
| 连线 | 只有两条：`BSDF → Output.Surface`、`game_atlas.Color → BSDF.Base Color` |
| DDS 解码 | `2014_mclaren_p1_ext_yellow.dxt.dds` 699,192 B → `(1024,1024)`、`has_data True`、`pixels[:4] = [0.902, 0.722, 0.031, 1.0]`（正是 `e8b808` 黄） |
| 已加载图片 | 40 张全部成功（14 车辆图集 + 4 `vehicles/common` + 23 张 ramp） |
| 有 UV 的网格 | 83/83 |
| 有 image 节点的网格 | 83/83（`simple` 模式下只有 43/83） |

⇒ 三个真实原因：

1. **6 个材质槽并存**，`poly.material_index` 只指向其中一个；
2. **`%TEMP%\rr3_dds` 里的解码文件重启即失效**，图片变粉色 —— 观感完全等于"没导入"；
3. 车漆的 Base Color 被图集贴图整个覆盖，而图集是"涂装色块 + AO/细节"，
   真正的主色在 `rm.paint_rgb` 里，所以即便连线正确也不像车漆。

## 2. 改动：单槽 + 多预设

### 2.1 新结构

```
<car>_<material>[_paint]        ← 一个 Blender 材质，挂在网格唯一的槽上
├── Material Output
├── preset_0 (NodeFrame "paint 1: <涂装名>")
│   ├── bsdf_0        Principled BSDF   ← 只有它连 Output
│   ├── atlas_0       TEX_IMAGE (REPEAT) → bsdf_0.Base Color
│   ├── ramp_fresnel_0   TEX_IMAGE (不连线)
│   └── ramp_specular_0  TEX_IMAGE (不连线)
├── preset_1 … preset_N-1  （同样结构，BSDF 不连 Output）
```

自定义属性：

| 位置 | 属性 |
|---|---|
| 材质 | `rr3_presets`（预设数）、`rr3_preset_names`、`rr3_preset_active`、`rr3_material`、`rr3_application`、`rr3_fresnel`、`rr3_specular` |
| 网格对象 | `rr3_paint_slots`（= 预设数）、`rr3_paint_slot`（当前）、`rr3_paint_presets`（名字表） |

### 2.2 关键代码

`rr3_blender_addon/__init__.py`：

```python
def _activate_preset(mat, index):
    nt = mat.node_tree
    out = next((n for n in nt.nodes if n.type == "OUTPUT_MATERIAL"), None)
    if out is None:
        return False
    for link in [l for l in nt.links
                 if l.to_node == out and l.to_socket.name == "Surface"]:
        nt.links.remove(link)
    bsdf = nt.nodes.get(f"bsdf_{index}")
    if bsdf is None:
        return False
    nt.links.new(bsdf.outputs["BSDF"], out.inputs["Surface"])
    mat["rr3_preset_active"] = index
    return True
```

`_build_preset_material(name, presets, active=0)` 里，预设 `order == 0` 的那个才连 Output；
`_apply_game_materials` 里 `me.materials.clear()` 后**只 append 一个**，
`for poly in me.polygons: poly.material_index = 0`。

`RR3_OT_switch_paint` 不再碰 `material_index`，只对选中对象的每个材质调 `_activate_preset`。

### 2.3 着色参数

| 输入 | 来源 |
|---|---|
| Base Color | 车漆族（`car_paint_*` / `car_bumper_paint_*`）用 `rm.paint_rgb`；其余用 `(0.8, 0.8, 0.8)`（**matte chassis 不该继承车身色**） |
| Roughness | `rm.roughness` = `sqrt(2/(SpecularPower_Base + 2))` |
| Metallic | `rm.metallic` = `clamp((fresnel_mean - 0.35)/0.40, 0, 1)` |
| Specular Tint | `rm.spec_colour` |
| Coat Weight / Roughness | 仅当 `SpecularPower_Top >= 200` 时 `1.0` / `rm.coat` |
| Alpha | `application == "appDepthSort"` 或 `GLASS` 标志 → `0.35` |
| Transmission | `GLASS` 标志 → `0.9` |

### 2.4 贴图打包

```python
img = bpy.data.images.load(path, check_existing=True)
if not img.packed_file:
    try:
        img.pack()
    except Exception as exc:
        print(f"warning: {name}: not packed ({exc})")
```

理由（已写进代码注释）：解码文件在 `%TEMP%`，会话之间会被清空；
不打包则重启后每张贴图变粉色，用户会认为"贴图从来没导入"。
代价是一台 6 涂装的车 .blend 大约多 15–20 MB。

## 3. 新增：私有贴图容器

### 3.1 `rr3lib/ddsdecode.py`

DXT1 / DXT3 / DXT5 解码，numpy 可用时走向量化路径，否则纯 Python。

| 项 | 值 |
|---|---|
| 两条路径一致性 | 三张样本 PNG **md5 完全相同**（`9483a49eae` / `dd78a90e12` / `203ec6924a`） |
| 速度（1024² DXT1） | numpy 0.043 s / pure 0.372 s |
| 速度（1024² DXT5） | numpy 0.064 s / pure 0.479 s |
| 与 Blender 自带解码 | 1024 个采样点 **0 处差异**（<0.004） |

API：`info(data)` / `decode(data) -> (w, h, 4, pixels)` / `backend()`。
`ATC ` / `ETC ` / `PVRTC` / `DX10` 明确抛 `DdsError`。

### 3.2 `rr3lib/texport.py`

| 后缀 | 布局 | 全库 |
|---|---|---|
| `.dxt.dds.z` | `u32 rawSize` + zlib → DDS | 21,446 |
| `.dxt.dds.z.bin` | `u32 0xFFFFFFFF, version=1, frames, flags` + 每帧 `[u32 comp][u32 rawSize]` + zlib | 924（阴影图，19–43 帧） |
| `.dxt.dds.bin` | 重复 `[u32 rawSize][raw DDS]`，**不压缩** | 2（实测 128 帧 × 32,900） |
| `.rgb.pvr.z` / `.ptc.pvr.z` | `u32 rawSize` + zlib → PVR | 3,229（车辆 12 个） |
| `.atc.dds.z` / `.etc.dds.z` | zlib → DDS，块格式 `ATC `/`ETC ` | 各 9（gui_assets） |

`selftest()` 输出：

```
.dxt.dds.z       1 frame(s) 1024x1024x4 DXT1
.dxt.dds.z.bin   22 frame(s) 512x512x4 DXT1
.dxt.dds.bin     128 frame(s) 256x256x4 DXT1
.rgb.pvr.z       1 frame(s) 64x64x4 PVR
.ptc.pvr.z       skipped
.atc.dds.z       skipped
4/4 container kinds decoded (2 skipped)
```

`.ptc` / `.atc` 只在 `gui_assets` 里，车辆从不用，所以是**识别但不解码**，
在 `selftest` 里算 skip 不算 fail。

### 3.3 `rr3lib/pvr.py` 扩写

支持 `.z` 容器 + bpp 32 / 24 / 16（掩码展开，默认 ARGB4444）/ 8（灰度）。
注意 PVR 头的 `dataSize` 是**含全部 mip 的总字节**，所以校验用 `w*h*(bpp//8)`。

`vehicles` 下 12 个 `.rgb.pvr.z` 里 **9 台车的 badges / wheel / misc 只有 PVR、没有 DDS 兄弟文件**：
`2008_bmw_z4_m`、`2012_audi_a5_touring`、`2016_mclaren_mp4x_uvc`、`2020_ligier_js_p320`、
`2022_bugatti_centodieci`、`2024_f1_haas_vf24`、`2024_hyundai_i20_n_rally1_wrc_11`（另两个是 decal 渐变）。

### 3.4 两个新 operator

| operator | 作用 |
|---|---|
| `rr3.export_textures`（*Textures ▸ Export textures*） | `source` / `target` / `fmt`(png\|dds) / `frame` / `skip_existing`，结果写 Text 块 `rr3_textures` |
| `rr3.load_textures`（*Textures ▸ Load car textures*） | 把整车目录的贴图全部加载进 `bpy.data.images`（含 ramp，标 Non-Color） |

## 5. 踩坑

- `bpy.data.objects["BODY"]` **不存在** —— 车身对象名是 `LOD_A_BODY_mm_ext`。
  按 `ob.get("rr3_mesh_name")` 找最稳。
- `bpy.ops.import_scene.rr3_vehicle` 只认 `filepath=`，传 `directory=` 会
  `TypeError: ... keyword "directory" unrecognized`。
- `smoke_materials.py` 里必须先 `addon.register()`，否则 `bpy.ops.rr3.switch_paint` 不存在，
  脚本会静默中断（表现为"只跑了前 9 项就 PASS"）。
- Blender headless 的 stderr 有几百行 `Failed to remove: ... PermissionError(13, '拒绝访问。')`
  （扩展清理噪音），会淹没 stdout。**必须把结果写进单独文件**，过滤时加 `-CaseSensitive`，
  否则 `FAIL` 会匹配到 `Failed to remove`。
- `python -c "..."` 里带中文和嵌套引号在 pwsh 下容易被解析坏，用 here-string 写临时 `.py` 再跑。
