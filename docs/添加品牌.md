# 添加品牌与 logo：小米 mod 的实证对照

对照对象：`E:\RR3_Nordschleife_SU7_Buyanbulak_v0.9.4_Full_From_Official_14.0.1_For_IOS_Android`
（官方 14.0.1 基础上加了一台 `2025_xiaomi_su7_ultra`，带一个全新的品牌 **Xiaomi**）。

## 1. 结论先说

**品牌就是一个字符串，不需要在任何表里"注册"。** 加一个小米品牌，这个 mod 只做了两件事：

1. **spec 里放品牌名**：`611_2025_xiaomi_su7_ultra.bin.nct` 解码后第一个字符串就是 `Xiaomi`
   （不是 `CAR_MANUFACTURER_XIAOMI`，是**字面量**；同一份文件后面还留着
   `CAR_MANUFACTURER_XIAOMI` 这个本地化键给文本表用）。
2. **logo 图集里加一行 + 一个新页面**，三个分辨率各一份。

没有新增厂家表、没有改索引、没有改 count 字段——这一点和 `rrmod/brands.py` 的判断一致：
"品牌在数据模型里不是一个必须存在的记录，它只是一段字符串，加上（可选的）一张图"。

## 2. 官方车的品牌名长什么样

| 车 | spec 解码后的开头几个字符串 |
|---|---|
| `88_2012_lexus_lfa` | `Lexus`, `LFAp`, `Supercar`, … |
| `101_2010_bmw_z4_gt3` | `Z4 GT3d`, `Race`, … |
| `611_2025_xiaomi_su7_ultra`（mod） | **`Xiaomi`**, `SU7 Ultra`, `Supercar`, … |

所以 spec 的"第三个 token"（`brands.py` 里说的那个位置）就是玩家看到的品牌名，
**写什么就显示什么**。BMW 那台第一位不是品牌，说明这个字段可以是本地化键，
也可以是字面量，引擎两种都认。

## 3. logo：图集加一行 + 加一个页面

`gui_assets/<size>/common/manufacturer_logos/sprites.android.atlas`（还有 `.ios.atlas`）：

官方三个尺寸都是 **65 张图**，页 0（480/960）或页 0/1/2（2048），
根标签带一个 `hash="J82exuq1MmpI765OpKwvBg"`。

小米 mod 在每个尺寸里追加了一行，并且**把根标签的 `hash` 属性删掉了**：

| 分辨率 | 追加的行 | 新页面文件 |
|---|---|---|
| 480x320 | `<image name="logo_xiaomi.png" ver="0" width="120" height="120"><pos id="1" x="4" y="4"/></image>` | `sprites_1.rgb.pvr.z` |
| 960x640 | `<image name="logo_xiaomi.png" ver="0" width="240" height="240"><pos id="1" x="8" y="8"/></image>` | `sprites_1.rgb.pvr.z` |
| 2048x1536 | `<image name="logo_xiaomi.png" ver="0" width="480" height="480"><pos id="3" x="16" y="16"/></image>` | `sprites_3.rgb.pvr.z` |

要点：

- **页面号 = 原来的最大页号 + 1**（2048 原来有 0/1/2，所以是 3；480/960 原来只有 0，所以是 1）。
  图集是**紧挨着排满的**，里面没有空位，所以新图只能单独占一页。
- 页面文件命名 `sprites_<页号>.rgb.pvr.z`，内容是 PVRTC + zlib，和同目录其它页一样。
- 图片尺寸正好是分辨率的 1/4（120/240/480），位置是 4/8/16 像素——**按分辨率等比**。
- **没有 `<hash val=.../>` 子元素**。官方每张图带 `<hash val="..."/>`，新加的这张没有，
  同时根标签的 hash 也被删了。这是唯一"被实机验证过能加载"的写法。

> 我们原来的 `rrmod/atlas.py:add_picture()` 会写一个**编造的** `<hash val="rrmodCustomImageN"/>`
> 并保留根 hash。2026-11-17 已改成和小米 mod 一致：不写子 hash、删根 hash。

## 4. 三个分辨率都要补

`gui_assets` 下按屏幕分档：`480x320`、`960x640`、`2048x1536`。
只补 2048 的话，低分辨率设备上这台车会**没有 logo**（图集里查不到 `logo_xiaomi.png`）。
官方在这三档的图集是同一份内容（同样的 65 张图、同样的 hash），
所以品牌图必须三档都加，且尺寸按 1/4 缩放。

## 5. 完整步骤（做一台新品牌的车）

1. **造车**：spec 里把品牌字段写成字面量 `Xiaomi`（工作台"构建车辆"里填品牌名即可），
   显示名 `SU7 Ultra`，同时在文本表里加 `CAR_MANUFACTURER_XIAOMI = Xiaomi` 之类的本地化键。
2. **图**：准备一张方形 logo（透明 PNG 最好），缩到 480/240/120 三档。
3. **图集**：三个尺寸的 `sprites.android.atlas`（和 `.ios.atlas`，若存在）各追加一行，
   页号取"最大页号 + 1"，同时删掉根标签的 `hash`。
4. **页面**：把图编码成 `sprites_<页号>.rgb.pvr.z` 放进同目录。
   工作台里是"品牌 logo"面板 → 选品牌 → 选图片，`brands.add_logo()` + `atlas.add_picture()` 做这件事。
5. **部署**：`deploy` 会把 `gui_assets` 下改过的图集和页面一起推上去。

## 6. 和我们的实现对照

| 环节 | 小米 mod | `rrmod` |
|---|---|---|
| 品牌名 | spec 里一个字面量字符串 | `brands.py` 认识这个字段，构建车辆时写入 |
| 已有品牌的 logo 替换 | 没做 | `brands.add_logo()`，`brandsui.py` 面板 |
| **新增**品牌 | 图集加行 + 新页面 | `add_picture()` 已按同样规则写（页号 = max+1、不写子 hash、删根 hash） |
| 多分辨率 | 三档都补，尺寸 1/4 | `brands.atlases(depot)` 会列出所有存在的图集，UI 里逐档写 |
| 本地化键 | 保留 `CAR_MANUFACTURER_XIAOMI` | 文本表编辑在 `translate.py` |

## 7. 没验证的事

1. `.ios.atlas` 是不是 iOS 包才用（Android 包改了 `.android.atlas` 就够）——
   mod 两份都改了，保险起见我们也两份都写。
2. 根标签 `hash` 到底有没有被校验。删掉能跑，说明**要么不校验，要么校验失败也不致命**；
   保留一个过期的 hash 反而更可疑。
3. 新页面放在 (0,0) 还是 (16,16) 有没有影响——mod 放在 16,16，我们在 (0,0)，
   两者都应该只是页内偏移，但没实测过 (0,0)。
