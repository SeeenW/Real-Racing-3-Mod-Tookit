## 3. 造车（`rr3.build_car` / `rr3lib.car.build_car`）产出的 10 个产物

输出目录是**游戏 `files/` 目录的镜像**，可以整目录推设备：

```
<out>/.depot/vehicles/data/611_<新车名>.bin.nct          ← spec（车辆规格）
<out>/.depot/vehicles/data/cardesc.list.nct              ← 车辆描述表（追加 1 条）
<out>/.depot/vehicles/data/suspensionbehaviour.suspensiondata.nct  ← 140 B 记录
<out>/.depot/vehicles/data/cardamagethresholds.damage.nct          ← 116 B 记录
<out>/.depot/vehicles/data/carappearances.appearances.nct          ← 外观块
<out>/.depot/vehicles/data/liveries/<新车名>.liveries.bin.nct      ← 涂装表
<out>/.depot/vehicles/data/liveries/{liveryStringTable,default}.bin.nct ← 从 donor 复制（seed_shared）
<out>/.depot/vehicles/<新车名>/…                         ← 55 个文件（11 m3g + 贴图 + points + livery/）
<out>/.depot/asset_list_base.txtCache.txt                ← 注册表（47,120 行）
<out>/apk/res/asset_list_vehicle_<新车名>.txt            ← 车辆清单（87 行）
<out>/apk/res/asset_list_vehicle_data.txt                ← 数据清单（1,139 行）
```

### 三条必踩的坑（都已写进代码注释和手册）

1. **donor 命名的别名副本**：贴图名烘在 `.m3g` 里，改名后引擎按老名字找图，
   找不到就**全洋红**。`build_folder()` 会给每个改名的文件在同目录再复制一份 donor 原名副本。
2. **`DeployWhenBraking` 只能原地替换**：`generic_race` 前必须正好是一个空 token
   （`\x00\x00\x00\x00\x0c\x00\x00\x00generic_race`），插入会移动后面所有字段，
   引擎在 `+0x18` 读空指针直接崩。`spec.set_aero()` 会断言这个空 token 全文件只出现 1 次。
3. **尾翼材质要显式继承**：donor 没有尾翼零件，livery 表里也就没有 `745` 这一行，
   引擎退回 `car_flat` ⇒ 纯黑。`build_livery()` 会调 `copy_body_paint()` 给每个涂装补
   `745 -> 与 30 相同`。

### donor 选择规则

- **必须有 appearance 记录**：540 个 spec 里有 **63 个没有**（F1 涂装车、`1968_porsche_909_bergspyder` 等，
  它们复用别的车体）。这类车的车目录也不存在。`build_spec` 遇到 `appearance_id == 0` 会失败。
- **别靠 spec 文件名 join 车目录**：352 个 spec 的名字和目录名不一致
  （`2012_aston_martin_one77` vs `2012_astonmartin_one77`）。正确做法走
  `appearance.load(depot)` → `by_id[spec.appearance_id()].name`。

## 4. `rr3lib/spec.py` 的两个定位器修复（重要，别改回去）

### 4.1 外观 id：`TOKEN_APPEARANCE = 86` 只对 218/540 成立

**根因**：`tokenize()` 把字符串读成 `u32 len` + 精确 `len` 字节，但文件把每个字符串**补零到 4 字节边界**。
补零在 token 流里变成数量不等的零 token ⇒ 外观 id 的索引在 **84–112** 之间浮动。

**修法**：按字节形状定位，不看索引。

```
_zero_run_before / _zero_run_after / _printable_run_before / _string_length_after
appearance_candidates(raw) -> [(offset, value)]      # 2 <= value <= 2000，前≥4 零，前有≥3 可打印字符
locate_appearance(raw) -> offset | None              # 多候选取"后零最长、后串最长、前零最长"
patch_appearance_id(raw, value, *, old=None)         # 优先信任 locate，old 只做交叉校验
```

**校验**：`tools/_spec_validate.py` → 188/188 正确、540/540 no-op 重写字节不变；
`tools/_spec_change2.py` → 真实改值 477/477 通过。

### 4.2 显示名：`TOKEN_DISPLAY_NAME = 105` 同样不可靠

`CAR_NAME_*` 的索引分布是 103–120 之间浮动，33 个 spec 完全没有，115 个有两个。

**修法**：`_locate_name()` 的优先级是

1. `CAR_MANUFACTURER_*` 字符串 token 的**紧邻下一个字符串**（`manuf_next`）
2. 否则第一个 `CAR_NAME_*`（`name_first`）

**为什么 manuf_next 优先**：`352_2019_formula_1_academy_car` 这类车有 `CAR_NAME_XX` + `CAR_NAME_XX_SHORT`
两个，且 SHORT 排在前面；按 name_first 取会取到残留的那个。改成 manuf_next 优先后，
rename readback 失败从 120 个降到 **5 个**（Koenigsegg Regera / Alfa 4C / Shelby GT500 / Jesko Absolut /
Battista Furiosa —— 它们的厂商串被拆成数字 token，**文件里的值是对的，只是读不回来**）。

**`set_display_name` 绝不插入 token**：33 个没有显示名 token 的 spec 直接返回 0 不改。
插入会移动后面所有字段（和 `DeployWhenBraking` 是同一条教训）。

## 5. 动画的三层载体（写文档的核心结论）

| 载体 | 决定什么 | 在哪 |
|---|---|---|
| `.banim` | **能不能动**、每个零件的 6 通道关键帧 | `<车>_wing.banim`（53 台有） |
| `_animations.xml` | **动哪一段**（片段名 → 帧范围） | `<车>_animations.xml`（53 台有） |
| spec 里的行为串 | **什么时候动** | `generic_race` 前一个 token |

### 5.1 12 个官方片段名与用量（全库 53 台）

`wing_initial` 53、`pivot_up` 41、`pivot_down` 41、`wing_up` 33、`wing_down` 27、
`wing_race_initial` 8、`neutral_to_speed` / `speed_to_neutral` / `speed_to_brake` /
`brake_to_speed` / `neutral_to_brake` / `brake_to_neutral` 各 6。

组合分布：17×（wing_initial + up + down + pivot_up + pivot_down）、14×（wing_initial + 两个 pivot）、
8×（上面 + wing_race_initial）、6×（完整 7 段）、4×（wing_initial + wing_up）、
2×（wing_initial + up + 两个 pivot）、2×（wing_initial + up + down）。

### 5.2 行为串（全库 540 台）

空 476、`NascarAirBrake` 40、`DeployWhenBraking` 13、`PaganiHuarya` 2（**官方拼写就是 Huarya**）、
`DeployAtSpeed, 120, 60` 2、`EngineFan` 2、`BrakeAndSpeedCombo, 180, 170` 2、
`BrakeAndSpeedCombo, 120, 80` 1、`DeployAtSpeed, 275, 220` 1、`None, 180, 170` 1、
`DeployAtSpeed, 100, 60` 1、`BrakeAndSpeedCombo, 100, 60` 1。

格式是自由文本 + 逗号参数：`<Behaviour>[, <arg1>, <arg2>]`，引擎按前缀认。

**关键反例（别写成"必要条件"）**：53 台有 `_wing.banim` 的车里只有 7 台用 `DeployWhenBraking`，
**16 台完全没有行为串却有尾翼动画**。

### 5.3 静态尾翼 vs 主动空力互斥

- 有 `HINGE_WING_REAR_LEFT/RIGHT` 的 17 台**全是 NASCAR**，且**全无** `_wing.banim`；
- 有 `_wing.banim` 的 53 台车**全部 0 条** WING 铰链（`HINGE_WING_REAR` 全库 0 命中）。

⇒ 想让尾翼动，走 banim；想固定角度，走 `.points` 铰链。

## 6. 导出侧的三条坐标系事实（`rr3_export.py` docstring 也写了）

1. **动画基就是 Blender 基** —— `cm @ ANIM_TO_MODEL == 单位阵`，
   所以 `AERO_*` 空物体的 `location` / `rotation_euler` **就是**引擎值（米 / 弧度），导出原样读。
2. **锚点不在这个基里** —— 导入是 `Rot180Z @ engine`，导出即 `engine = Rot180Z @ blender`（180° 绕 Z 自逆）。
3. **一轨 = 一个零件，6 通道** —— `pos xyz`（米）+ 欧拉 `xyz`（度），存相对静止姿态的**增量**。

导出 `.banim` 时**必须求值关键帧**（`_pose_at` 会 `frame_set` 再读对象）。
第一版直接读对象属性，结果所有帧写成同一个当前姿态。
