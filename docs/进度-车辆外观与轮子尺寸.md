## 已确认结论

| 现象 | 数据来源 |
|---|---|
| **轮毂样式 + 轮胎尺寸** | `vehicles/data/carappearances.appearances.nct`，每车 266 字节外观块（f1/f5 = 前/后加载轮胎半径，已确证；见 `points-格式.md` §9） |
| 悬架行程 / 离地高度 | `vehicles/data/suspensionbehaviour.suspensiondata.nct`，每车 140 字节记录（+43~45，即 floats 23/24） |
| 轮胎直径（物理，自由半径） | 同上记录 **floats 21 / 22（0 基）**（Reventón 0.685/0.735，Chiron 0.740/0.780，GT3 RS 0.710/0.720，Megane Trophy R 0.670/0.670） |
| 性能数值（PR 面板那 4 个数） | `vehicles/data/<id>_<car>.bin.nct`（951 B，id 在 offset 4） |
| 尾翼展开条件 | 同上，字符串 `DeployWhenBraking` |

> ⚠ **2026-10-27 修正**：本表原来写"轮胎直径在 +22/+23"。按 140 字节记录的
> `u32 id + 34 floats` 布局实测 172 台，**0 基索引 21/22 才是前/后轮胎直径**，
> 22/23 会取出 0.017~0.058 这种荒谬值。FORMATS.md §1376 的括号索引是 1.2.10 版本的，
> 14.0.1 上偏移了 1。详见 `points-格式.md` §9。

**关键实验**：把 Reventón 的 266 字节外观块换成 Chiron 的（保留记录号与车型名）→ 用户确认「完全一致」。
副作用：离地高度可调范围变小（说明外观块里也带了悬架外观参数）。

## 文件结构

```
carappearances.appearances.nct  162,235 B
  header: u32 23, u32 540
  record: u32 记录号, u32 名字长度, name(ASCII), 266 B 位压缩外观块
  Reventón 0x2124c(rec 476, name 25B, blob 0x2126d)
  Chiron   0x125c4(rec 270, name 19B, blob 0x125df)

suspensionbehaviour.suspensiondata.nct  75,608 B
  header: u32 1, u32 540
  record: 140 B 定长（35 × u32），第一字 = 车辆 ID
  Reventón rec 459 (0xfb0c)，Chiron rec 204 (0x6f98)

<id>_<car>.bin.nct  951 B（Chiron 1045 B）
  +0 u32 71, +4 u32 车辆 ID, 之后 len+str 与 4 字节数值交替
  ⚠ 头部字段混有结构数据，整段替换会启动闪退
```

## .nct 加解密

`keystream = encrypted XOR decrypted`，**只与字节位置有关、与文件内容无关**。
用 `carupgrade.upgrades.nct`(603,513 B) 与其解密版生成，可覆盖所有 .nct：

```python
ks = bytes(a ^ b for a, b in zip(enc_bytes, dec_bytes))   # 长度 = 文件长度
data = bytes(a ^ b for a, b in zip(file_bytes, ks))       # 解/加密同式
```
