# 自制部件并入 RR3 车辆 —— 标准流程

这套流程的要点：**以原厂 `_a.m3g` 为基底**，只把自制部件合并进去。
不要用 Blender 整车往返导出的文件当基底——那样会把引擎合并过的原厂网格
重新切分，法向/锐边/三角划分全都变样（实测车体 5645 → 5045 三角）。

## 1. 在 Blender 里做部件

* 部件名必须与目标车原有部件名**逐字一致**（引擎按名字找网格，不认识的名字静默跳过）。
  新建部件用 `LOD_A_<部件>_mm_<tag>`，`<tag>` 取 `ext` / `misc` / `cab` / `lights` /
  `badges` / `chassis` / `windows` / `rim` / `tyre` / `rotor`。
* 同一个部件名下的多个网格（`_mm_ext`、`_mm_misc`）会一起运动，算 **1 条动画轨道**。
* 部件原点放在**铰链/转轴**上，模型坐标 +X 右、+Y 上、**−Z 车头**。
* 材质用 `Vehicle Exterior_mm_<tag>`，导出器按名字匹配到原厂材质表。
* 锐边：正常设 Sharp / Auto Smooth 即可，导出器现在读的是 **corner normals**（4.1+ 的
  `mesh.corner_normals`，旧版退回 `calc_normals_split`），锐边会保留。

## 2. 从 Blender 导出（只导部件）

`File > Export > RR3 Model (.m3g)`，**Template 选目标车的原厂 `_a.m3g`**。
模板用来取：材质名表、每部件的 81 B / 50 B 未知块、尾翼的 130 B 尾块。

## 3. 合并进整车

```bat
:: 3a. 替换已有部件（例如修好法向的保险杠）
python analysis\merge_parts.py <原厂_a.m3g> <out1.m3g> <导出件.m3g> --only FRONTBUMPER_mm_ext

:: 3b. 追加新部件（例如自制尾翼）
python analysis\add_parts.py <out1.m3g> <out2.m3g> <导出件.m3g> WING_REAR
```

`merge_parts.py` 直接拷原始 payload（不重编码），并且会一并把 VB 里的
`positionScale` / `positionBias` / UV 缩放换成 donor 的值。2026-10-25 起导出器
已默认按原厂定点写（`raw = 米 / scale`，模板优先、否则 `峰值/1024`），两边系数一致，
不再需要事后转换；仍不要手改回 `1.0`（引擎会换顶点路径，实机卡顿 + 丢高光）。
`add_parts.py` 在对象表末尾
追加五个顶点数组 + VB + IB + mesh，并把内部 1 基引用改写成新编号；材质按**名字**
解析到原厂材质表（必要时追加），材质表就地重写（引擎只认第一个材质表对象）。

> **基底必须先切掉要追加的部件。** 如果原厂车体里还焊着尾翼几何，再用
> `add_parts.py` 追加自制尾翼，就会看到“两个尾翼 + z-fighting”。
> 正确做法是：从 Blender 导出整车时**删掉该部件**，用这个导出件当基底
> （`merge_parts.py` 只替换几何、不新增网格），再追加新部件。

## 4. 法向（锐边 / 薄板反射）

如果部件是从车体上切下来的，它会继承车体的平滑法向，薄板上就会发暗。两种修法：

```bat
:: 逐面法向（硬表面薄板，推荐）
python analysis\flat_normals.py <in.m3g> <out.m3g> WING_REAR

:: 按角度重建（保留 <40° 的平滑、>40° 的锐边），可对整个车用
python analysis\rebuild_normals.py <in.m3g> <out.m3g> --angle 40 --match WING_REAR
```

判断指标：`corner normal` 与自己三角面法向的一致率（越接近 1 越好）。
原厂 `LOD_A_BODY_mm_ext` = +0.929（>0.99 占 55.7%），修好的尾翼 = +0.994。

## 5. 上车验证

```bat
python analysis\push_m3g.py test <file.m3g>     :: 自动备份 .orig、push、chown/chmod
python analysis\push_m3g.py restore             :: 还原原厂
```

* adb 端口每次可能不同：`adb connect 127.0.0.1:16416`（或 7555）。
* `adb push` 落成 `shell:ext_data_rw 644`，游戏 uid 读不到 ⇒ 必须
  `adb root` 后 `chown u0_a18:ext_data_rw` + `chmod 660`。
* 热重载：进车库切到别的车再切回来，会重新读 `_a.m3g`，不用重启游戏。

## 6. 自制动画（可选）

1. 用 `analysis\make_wing_banim.py` 克隆同结构车的 `_wing.banim`，只改关键帧值：
   位置 `raw = 米 × 65536`、旋转 `raw = 度 × 32768 / 180`。
2. 写 `<car>_animations.xml`：`wing_initial 0→0`、`wing_up 0→45`、`wing_down 45→0`
   （1 帧 = 33 ms，`end < start` 表示倒放）。
3. **必须把这两个文件加进 `apk/res/asset_list_vehicle_<car>.txt`**，格式
   `路径 \t md5 \t zlib压缩后大小 \t 原始大小`，否则引擎根本不会读。
4. 想让尾翼在刹车时展开，还要在车设定 `<id>_<car>.bin.nct` 里加 `DeployWhenBraking` 标记
   （`analysis\put_car_flag.py`）。

## 6.5 ★ 给新部件指定材质（liveries 表）—— 不做这一步新部件会发暗

**这是"部件出现了、能动、但材质是 `car_flat`（发暗、不跟随车漆）"的唯一原因。**

引擎按**网格名**去 `liveries/<车>.liveries.bin.nct` 里查材质。这个文件有 4 张表
（详见 `docs/livery槽位表与材质名.md`），其中两张是「零件 → 材质」映射：

```
str  车名
u32  n1, n1 × (u32 slot, str path)          # ① 贴图表
u32  n2, n2 × (u32 meshSlot, u32 matSlot)   # ② 网格 → 材质（全车通用）
u32  n3, n3 × (u32, u32, u32)               # ③
u32  n4                                      # ④ 涂装列表
n4 × { ... u32 m, m×(u32 slot, str path)     #    贴图覆盖
       u32 k, k × (u32 meshSlot, u32 matSlot) }  #    ★ 材质覆盖（按涂装，最具体）
```

`meshSlot` / `matSlot` 都是 `liveryStringTable.bin.nct` 的下标。
**关键槽位**：`30 = LOD_A_BODY_mm_ext`、`745 = LOD_A_WING_REAR_mm_ext`、
`747 = LOD_A_WING_REAR_mm_misc`、`738/742 = WING_REAR_LEFT/RIGHT_mm_ext`、
`750/753 = WING_STRUT*_mm_ext`、`757 = LOD_A_WING_mm_ext`。

**原厂的做法**：在每个涂装的「材质覆盖」里写 `745 -> 和同涂装 30 完全相同的漆种材质`。
全库 25 台车、59 个涂装这么写，16 组配对**无一例外**。
`747` 全库 0 命中——原厂从不给尾翼的 `_mm_misc` 补材质（那部分本来就是黑塑料）。

**我们的做法**（已自动化）：`analysis/newcar_build.py` 的 `build_livery()` 在写出前调用
`analysis/livery_write.py` 的 `add_wing()`，对每个涂装若 `30` 有覆盖而 `745` 没有，
就追加 `(745, 同 30 的目标材质)` 并按 slot 升序重排。

```bat
:: 单独给一个 liveries 文件打补丁
python analysis\livery_write.py --add-wing <in.liveries.bin.nct> <out.liveries.bin.nct>

:: 自检：对全库 541 个文件做 parse→serialize 逐字节往返
python analysis\livery_write.py --selftest
```

实测（611）：`4709 → 4749 B`，涂装 01–05 各 +1 条（涂装 06 本来就没有车身漆覆盖，跳过）。
部署后尾翼**和车身同色同光泽、跟随车漆类型变化**。

> **加任何新部件都要做这一步。** 只要新网格的零件名在 livery 表里查不到，
> 它就会拿到硬编码的 `car_flat`。注意 `default.liveries.bin.nct` 里虽然有一张
> 1867 条的「网格→材质」总表（`745 -> car_paint_gloss`），但**它不是运行时兜底**
> ——修复前尾翼拿到的正是 `car_flat` 而不是 `car_paint_gloss`，所以别指望它。

## 7. 常见坑

| 现象 | 原因 |
|---|---|
| 加载时闪退 | 只写了一节（必须两节）；`fileInfo.totalFileSize` 与实际不符；材质表里有未被引用的条目 |
| 部件不显示 | 网格名与目标车不一致 |
| 部件变得极小（缩成点） | `merge_parts.py` 只拷了顶点数组，没拷 VB 里的 `positionScale`/`positionBias`（旧版 Blender 导出是米、scale=1，原厂是定点 0.00219）。2026-10-25 起导出器默认写原厂定点，这个坑只剩“手工把 scale 改回 1.0” |
| 同一部件出现两遍 / z-fighting | 基底里还留着焊接版几何，又用 `add_parts.py` 追加了一份。基底必须已经**切掉**该部件 |
| 锐边全没了 | 导出器用了顶点法向而非 corner normals（已修） |
| 薄板发暗 | 顶点法向不匹配几何，用 `flat_normals.py` |
| **部件发暗、不跟随车漆** | **`liveries/<车>.liveries.bin.nct` 缺该零件的材质覆盖**（见 §6.5）。改 `.m3g`、改法向、改 UV 全都没用 |
| 尾翼不动 | `asset_list_vehicle_<car>.txt` 缺 `_wing.banim` 条目 |
| 推上去没生效 | `adb push` 后的属主/权限不对 |
