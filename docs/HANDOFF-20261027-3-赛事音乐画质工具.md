## 2. 地基：为什么改 `.depot/` 里的文件不会触发重下载

这一条是本轮全部三个工具能成立的原因，写在 `docs/清单校验与补丁.md` 里，这里复述：

1. 引擎有**两份**校验记录：
   - `files/apk/res/asset_list_base.txt` —— 4 列：`路径 \t md5 \t 打包大小 \t 原始大小`
   - `files/.depot/asset_list_base.txtCache.txt` —— 13 字节头 + `路径 \t md5`
2. 判定逻辑：**清单 md5 == 注册表 md5 且文件存在 ⇒ 视为最新，永不下载。**
3. Android 引擎**从不现场算 md5**（`.so` 里 `Utility::MD5HashString not is implemented in Android`），它只信那两个文本值。

⇒ 推论：
- **不动清单**：改 `.depot/` 里的文件内容，两边 md5 仍相等 ⇒ 不重下，读到我们的版本。（音乐、画质走这条路）
- **动清单**：把两处 md5 同步成新文件的 md5 ⇒ 也不重下。（赛事走这条路，因为要新增文件）

## 4. ② 赛事音乐 —— `analysis/music_tool.py`（318 行）

### 4.1 原理（实测结论，写在文件头 docstring 里）

每条赛道有自己的**播放列表**，存在 `files/.depot/Tracks/data/<track>-<time>-<id>.bin.nct`。
`.nct` 解密后是一个纯 **「key(4B) / len(4B) / value(len B)」记录流**（168 个文件全部能整段解析完，`consumed == filesize`）。

三条记录的 key 是固定的属性名哈希：

| key | 含义 |
|---|---|
| `0xBB463310` | `Music_Track_1` |
| `0xBB463313` | `Music_Track_2` |
| `0xBB463312` | `Music_Track_3` |

value 就是 `audio/music/` 下的**文件名**，如 `Ryan_Kurt_Taplein_SIPPY_Remix.mp3`。
⇒ **"改赛事音乐" = 改这三条记录的值，完全不用碰 `audio_music.bin.ncm`。**

`audio/music/*.mp3` 本身是**明文 MP3**（帧头 `FF F3 94 64`）。菜单/加载音乐走硬编码路径，直接换文件内容即可：
`Menu_Music.mp3`、`Garage_Music.mp3`、`LoadingScreen.mp3`、`IntroCinematic.mp3`、`IntroLogos.mp3`、`Ryan_Kurt_Connected.mp3`。

**不用改清单**（理由见 §2）：不动清单 ⇒ 两边 md5 仍相等 ⇒ 引擎不重下。

### 4.2 子命令

```
list [filter]                列出 168 条赛道的三个槽位
songs                        列出可用的 mp3
set --track|--group|--all --song ... [--no-deploy]
deploy                       推到设备
verify                       核对
import-song <本地.mp3> <游戏内名.mp3>    装自己的歌
```

`set` 参数细节：
- `--track` 赛道文件名子串，如 `Bathurst`
- `--group` 一组赛道，如 `formula_e`
- `--all` 全部 168 个
- `--song` 可重复，**按 Music_Track_1/2/3 顺序填，不足 3 首循环补齐**
- `--no-deploy` 只生成不推

### 6.2 `analysis/so_patch.py`（160 行）—— `.so` 原地补丁

```
info / export <out.bin> / patch --at <off> --hex <bytes> / push [--no-launch] / restore / launch
```

`.so` 在 apk 内是 **STORED 未压缩**，可以原地改字节，**不重签 apk**。root 设备直接覆盖 `/data/app/.../base.apk`，下次启动 linker 就会 mmap 新的。

**已装机的那 8 字节补丁**（历史遗留，效果 = 调试赛事按钮 `BTN_DEBUG_RACE` 恒显示）：

| 项 | 值 |
|---|---|
| APK 内偏移 | `0x4EB7FE4`–`0x4EB7FEB` |
| `.so` 内偏移 | `0xD9BFE4`（对应 Ghidra VA `0x00E9BFE4`） |
| 原始字节 | `c8 00 00 34` (`cbz w8, +0x18`) + `f7 31 0d 94` (`bl FUN_011e87c4`) |
| 补丁后 | `1f 20 03 d5` (`nop`) + `20 00 80 52` (`mov w0, #1`) |
| 设备 base.apk md5 | `40c7bca0c2417fba9e30bc5a2d469efd` ✅ 已装 |
| 原版备份 | `work\sopatch\base_original.apk`（md5 `e5f21b6fdb655c71dfed7ae81022ef7b`） |
| 补丁版 | `work\sopatch\base_patched.apk`（md5 `40c7bca0…`） |

⚠️ 用 `zipfile` 读 `base_patched.apk` 会抛 `BadZipFile: Bad CRC-32 for 'lib/arm64-v8a/libRealRacing3.so'` —— **这是预期的**（原地改字节没更新 CRC）。取原始 `.so` 请从 `base_original.apk` 或 `re\lib\libRealRacing3.so`。
