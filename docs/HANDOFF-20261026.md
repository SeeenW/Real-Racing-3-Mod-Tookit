**机制要点（都实测过）**
1. **spec token 86 = appearance 记录 id**。不改它，车就借用 donor 的资产目录/清单/liveries。
2. appearance 记录的 `name` 决定三件事：资产目录名、`asset_list_vehicle_<name>.txt`、`liveries/<name>.liveries.bin.nct`。
3. 清单/注册表只比**文本 md5**，文件内容随便改都不触发下载；判定是逐条比对，最终门是 `LoadAssetList` 累计的待下载字节 == 0。
4. `DeployWhenBraking`（写在 spec 里 `generic_race` 前那个 4 字节空 token 处，**替换而不是插入**，插入会崩 `null ptr 0x18`）是"主动空力"总闸：**没有它，`_wing.banim` 加载了也不会生效**；没有 `_wing.banim` 时引擎会打 `has animation-dependent active aerodynamics but no animation could be found!!`。
5. 显示名：spec 里的显示 token 会被转大写、加 `GAMETEXT_` 前缀去 `gametext.txt` 查；所以往文本表里插 key（`GAMETEXT_LFA-ANIMTEST` 等 5 个候选）就能显示 `LFA-ANIMTEST`。文本表是 **RC4，密钥由输入文件名派生**（见 `analysis\insert_carname_text.py`）。
6. 赛事：`monkeytool_cli.exe rr3 rr3series add <depot> re\series_out template=8 title=... cars=611 event="Laguna Seca:2:3" group=STREAM_GROUP_PRO` → series 10000，产出 14 个文件由 `patch_series.py` 并入。

**MonkeyTool 用法**（rr3 子命令**不加 `nfsnl` 前缀**）：
`tools\Monkey.Tool.1.3.1\monkeytool_cli.exe rr3 <cmd> <gameFolder> ...`，`gameFolder` = `...\files\.depot`。
`decode/encode` 处理 `.nct/.gui/text_*.txt/gametext.txt` 的 RC4。另有 QuickBMS 脚本 `tools\nct2xml\rr3_encryptedxmlwriter.bms`（KEY=`a5 35 b3 b1 e8 43 c7 cf`… 实为 `a5 35 b3 b1 e8 43 e7 cf`），**没有 603,513 B 的长度上限**，能解 `events.dat.nct` 之类大文件。

## 4. 尾翼问题：现在知道什么

### 4.1 已证实的关键机制（别推翻，都是实测）

1. **尾翼是"动画部件"**：把 `_wing.banim` 和 `_animations.xml` 从车上删掉后，**即使把尾翼顶点抬到车顶上方 1.45 m，引擎也完全不画它**（`re\shot_noanim1.png`）。有动画 → 画；无动画 → 不画。
2. **它拿到的材质是 `car_flat`**：RenderDoc 里那一发 `uniforms34` 的 `_child1 = 0,0,0 / 1`，与 `materials.bin` 的 `car_flat` 记录逐字一致（`mu_MaterialSpecularColour_Base=0,0,0`、`Power=1`、`[3]fresnel_flat.pvr`＝全库唯一纯黑渐变）。所以尾翼**不跟随车漆类型**（哑光漆仍带清漆高光、金属漆没有珠光）。
3. **`_mm_<tag>` 只决定 albedo 图集与渲染分组**：改成 `_mm_badges` 会采到黑格栅、`_mm_lights` 采到车灯图、`_mm_wheel/_mm_tyre` 则**整个不被绘制**（车轮走另一条通路）。
4. **材质是按 tag 存在 part 对象里的**：`FUN_0166866c` 里 `part[+0x10] = *(car + tagIdx*8 + 0x3248)`，`tagIdx` 由 `FUN_01668324` 用网格名 `<零件名>[_cN]_mm_<tag>` 在 21 条 tag 表里 `strcmp` 得到（`ext`=0）。换漆时 `FUN_01678a5c` 造新材质并**按旧指针相等**批量替换所有 part。车身与尾翼 tag 都是 `ext`，理论上应同材质 —— 与实测矛盾，**这就是要查的点**。
5. 网格侧已与 P1 逐字节等价（82 B 附加块全同、网格名的 4 个差异字节只是对象引用），**数据侧已无可调参数**。

## 6. 硬约束 / 血泪教训

1. **不要改网格名**（改了就丢动画绑定或不被绘制）；**不要动 UV**（用户明确禁止）；**不要改尾翼索引缓冲的数量**（必崩）。
2. `newcar_deploy.py push` 前必须 `adb root`，否则 `chown: Operation not permitted`。
3. `--extra` 按**文件名 basename** 命名产物，别传 `tmp_xxx.xml` 这种名字（会在清单里留 0 B 坏条目）。
4. `adb logcat -c` 后引擎不会补发日志；必须**重启前开始流式抓**。
5. **不要用 atime 判断设备上文件是否被读**（挂载等价 noatime）。
6. m3g 引用是 **1 基**索引；每段尾部 4 字节校验恒 0；`totalLength = payload + 13`；段内对象流，改长名字只改对象长度与段长度（`analysis\m3g_rename_part.py --selftest` 可逐字节自证）。
7. 本包 `positionScale` 每车不同（LFA `0.0021973606199026108`、P1 `0.0023481915704905987`），顶点存的是 **float32 的定点原始值**（米 = 值 × positionScale）。
8. `Fn.java` 输出混用 `\r\n` 与孤立 `\r`，读之前先归一化换行。
9. 机器**连不上 GitHub**（`schannel ... SEC_E_NO_CREDENTIALS` / 443 不通），要外部仓库只能让用户下载到 `tools\` 或 `re\ext\`。
