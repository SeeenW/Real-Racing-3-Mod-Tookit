## 0. 一句话结论

用户报的三件事，**根因全部找到并修完**：

| 用户说的 | 真正的根因 | 修法 |
| --- | --- | --- |
| 这次材质没有导入进去 | `_apply_game_materials()` 里 `find_depot()` 返回 `None` 时**静默 `return None`**，一个 warning 都不写。车目录一旦离开 depot（拷出来、或层级超过 8 层）整条游戏材质链路就被跳过 | 改成**抛错**，由导入器记成 `game materials: cannot find the depot's materials/materials.bin above …`；新增 operator 参数 `material_depot`（Depot 目录），指一下就修好 |
| 加载贴图只加载了选中文件夹里的，子文件夹的 `livery` 没加载 | `_load_car_textures()` 用平铺 `os.listdir(car_dir)`，而涂装图集在 `<车>/livery/` 下 | 改成 `os.walk`，抽成 `_car_texture_files()` |
| 加载贴图时没清理掉未垂直翻转的贴图 | ①解码产物固定写 `<temp>/rr3_dds/`，与上一版同名 ②Blender 的 `images.load(check_existing=True)` **只按路径命中、不重新读盘**，所以翻转后的新 PNG 写出来了，场景里显示的还是旧像素 | ①缓存目录分版本 `<temp>/rr3_dds/v2/`（`TEXTURE_CACHE_VERSION = 2`）②新增 `_purge_stale_textures()` 删旧目录/散落文件 + 删引用它们的 `bpy.data.images` ③新增 `_adopt_image()` 按文件名找到旧图像后改 `filepath` 并 `reload()` |

顺带修掉一个同类隐患：`_build_preset_material()` 里同名材质**直接 `return mat`**，不校验预设数，
同一会话里先 `simple` 后 `game`（或导入两台同名车）会拿到预设数不对的旧材质。
现在校验 `mat.get("rr3_presets") == len(presets)`，不符就 `bpy.data.materials.remove(mat)` 重建。

所以问题在**入口**，不在链路。`find_depot()` 是「从车目录向上最多 8 层找
`materials/materials.bin`」：

```python
def find_depot(start: str) -> str | None:
    cur = os.path.abspath(start)
    for _ in range(8):
        if os.path.isfile(os.path.join(cur, *MATERIALS_BIN.split("/"))):
            return cur
        parent = os.path.dirname(cur)
        if parent == cur:
            break
        cur = parent
    return None
```

车在 `<depot>/vehicles/<car>` ⇒ 3 层内命中。**但车目录一旦不在 depot 里（拷出来、或从
别的盘符挂进来），就找不到，而调用方是静默返回**：

```python

if depot is None:
    return None          # ← 一个字都不说
```

### 2.1 修法

`_apply_game_materials(objects, car_dir, car, paint=-1, depot=None)`：

```python
if depot is None:
    depot = gamematlib.find_depot(car_dir)
if depot is None:
    raise RuntimeError(
        "cannot find the depot's materials/materials.bin above "
        f"{car_dir}; pick the depot folder explicitly in 'Depot' to get the "
        "game's own materials")
```

导入器侧把它记成 warning 并 `print`（以前连 warning 都没有）：

```python
try:
    game_materials = _apply_game_materials(every, car_dir, car, paint,
                                           depot=material_depot or None)
except Exception as exc:  # noqa: BLE001 - never fail the import for this
    msg = f"game materials: {exc}"
    plan.warnings.append(msg)
    print(f"[rr3] {car}: {msg}")
if game_materials is None and not any("game materials" in w for w in plan.warnings):
    msg = ("game materials: the depot's materials/materials.bin was not "
           f"found above {car_dir}, so the placeholder materials were "
           "kept - set 'Depot' to the .depot folder to use the game's own")
    plan.warnings.append(msg)
    print(f"[rr3] {car}: {msg}")
```

新参数 `material_depot: str = ""`（`import_vehicle_file`）与 operator 上的
`material_depot: StringProperty(name="Depot", subtype="DIR_PATH")`，
`execute()` 里 `material_depot=bpy.path.abspath(self.material_depot) if self.material_depot else ""`。

## 3. 贴图漏 `livery/`

`_load_car_textures()` 原来是：

```python
names = sorted(os.listdir(car_dir))
...
if not os.path.isfile(path):
    continue
```

只扫一层。而车漆图集在 `<车>/livery/`：

- `2014_mclaren_p1`：根目录 18 个贴图文件 + `livery/` 6 个
  （`_ext_black/blue/orange/silver/white/yellow.dxt.dds.z`）
- `2011_pagani_huayra`：根 18 + `livery/` 6

实测旧版 `_load_car_textures` 返回 `images 84`（72 张 ramp + 12 张图集），
**`_ext_<colour>` 一张都没进** —— 与用户描述完全一致。

修法：

```python
def _car_texture_files(car_dir: str) -> list:
    """Every texture file of a car, **including the ones in sub-folders**.

    The paint atlases live in ``<car>/livery/``, not next to the body, so a flat
    ``listdir`` silently skipped exactly the textures a paint scheme needs.
    """
    found = []
    for root, _dirs, files in os.walk(car_dir):
        for name in sorted(files):
            path = os.path.join(root, name)
            if texportlib.is_texture(path):
                found.append(path)
    return found
```

`_load_car_textures()` 改用 `for path in _car_texture_files(car_dir)`，
报错名用 `os.path.relpath(path, car_dir)`（这样能看出是 `livery\xxx` 还是根目录）。

**注意导出侧本来就没这个问题**：`texport.export_tree()` 一直是 `os.walk`，
只有加载侧漏了。

实测：`2014_mclaren_p1: total 18 in livery/ 6`、`loaded 90 failed 0`，
`paint atlases: _ext_black/blue/orange/silver/white/yellow`（+ `_ext_shadows_high`）。

## 4. 旧解码不清理

### 4.1 为什么仅覆盖文件不够

`_image_for_path()` 走 `texportlib.export(path, _image_cache_dir(), "png")`
→ `pvrlib.write_png` 直接覆盖同名 PNG。但 Blender 侧：

```python
img = bpy.data.images.load(png, check_existing=True)
```

`check_existing=True` **按文件路径命中已加载的图像**，而 Blender 对已加载图像
**不会重新读盘**（像素已在内存）。所以翻转后的新 PNG 写出来了，场景里显示的
还是上一版的像素。加上上一版文件名与新的一致，只靠覆盖永远刷不新。

### 4.2 三层修法

**① 缓存目录分版本**

```python
TEXTURE_CACHE_VERSION = 2

def _image_cache_dir() -> str:
    return os.path.join(tempfile.gettempdir(), "rr3_dds",
                        f"v{TEXTURE_CACHE_VERSION}")
```

旧版（未翻转）落在 `<temp>/rr3_dds/*.png`，新版落在 `<temp>/rr3_dds/v2/*.png`，
路径不同 ⇒ 永远不会被误命中。

**② `_purge_stale_textures()`**

删三样，都只碰我们自己的东西：

- `<temp>/rr3_dds/` 下非当前 `v<n>` 的子目录（`shutil.rmtree`）
- `<temp>/rr3_dds/` 下散落的 `.png` / `.dds`
- `bpy.data.images` 里 filepath 落在 `<temp>/rr3_dds/` 但不在当前版本目录下的图像
  （`commonpath` 判归属，`ValueError` 兜不同盘符）

返回 `{"files": n, "images": n}` 供报告。锁住的文件/在用的图像吞掉不报错
（`OSError` / `Exception`），"不值得为它让导入失败"。

**③ `_adopt_image(png)`**

按**文件名**找到旧路径的图像，改 `filepath` 再 `reload()`：

```python
stem = os.path.basename(png)
for img in bpy.data.images:
    current = bpy.path.abspath(img.filepath) if img.filepath else ""
    if os.path.basename(current) != stem or current == png:
        continue
    img.filepath = png
    try:
        img.reload()
    except Exception:
        pass
    return img
return None
```

这样已经引用该图像的材质会刷新到新像素，不需要重建整个场景。
`_image_for_path()` 与 `_ramp_image()` 都改成先 `_adopt_image(png)`、没有再 `load`。

## 5. 顺带：材质名复用不校验预设数

```python
mat = bpy.data.materials.get(name)
if mat is not None:
    return mat          # ← 旧
```

改成：

```python
mat = bpy.data.materials.get(name)
if mat is not None:
    # A material of that name can be left over from an earlier import with a
    # different scheme count (a car repainted, or a second car reusing the
    # name).  Rebuilding beats silently handing back the wrong presets.
    if mat.get("rr3_presets") == len(presets) and mat.node_tree is not None:
        return mat
    bpy.data.materials.remove(mat)
```

实测「先 simple 再 game」：28 个材质，预设数 `{_paint: 6, 其它: 1}` 全部正确；
「game 连跑两次」也 `{'FINISHED'}`。

## 8. 环境备忘

- depot 根：`E:\DXT_480x320+960x640+2048x1536数据包-Build260716\files\.depot`。
  **中文路径在 pwsh here-string 里写死会变乱码**，用 `glob.glob(r"E:\DXT*Build260716")[0]`。
- `bpy.ops.import_scene.rr3_vehicle` **只认 `filepath=`**，且必须指向具体 `.m3g`；
  传文件夹会让 `car_from_path` 把 `car` 认成 `vehicles`，报
  `no LOD A body found for <car> in ...\vehicles`。
- Blender headless 的 stderr 有几百行 `Failed to remove: ... PermissionError(13, '拒绝访问。')`
  （扩展清理噪音）。**stdout 单独重定向到文件**再读，`Select-String` 必须加 `-CaseSensitive`。
- 同一进程里连续导入多台车，每台前要 `bpy.ops.wm.read_factory_settings(use_empty=True)`
  + `addon_enable`，否则 `bpy.data.*` 会留着上一台。
- `python -c` 里带中文/嵌套引号在 pwsh 下会被解析坏，用 here-string 写临时 `.py` 再跑。
