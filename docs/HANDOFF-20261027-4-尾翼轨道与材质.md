## 0. 一句话结论

- **部件→轨道的配对不靠名字顺序，靠网格对象自带的 keyframe 表**。`.m3g` 的每个网格对象
  尾部有一段未解析字节（`rr3lib/m3g.py:537` 的 `_unparsed`），结构是
  `u32 count` + `count × {u32 time, u32 16384, u16 0, f32 value}`（14 字节/条，
  `4 + count*14 == _unparsed`）。**带这张表（`_unparsed > 4`）的部件就是会动的那个**。
  全库 106,399 个网格里只有 93 个带表，0 个畸形。
- **材质走游戏自己的三级链路**：`网格名 → liveryStringTable 部件槽 → 材质槽
  （涂装覆盖 → 车表 → default）→ 材质名 → materials.bin 的着色器 + 两条 LUT 色带`。
  每套涂装生成一套 Blender 材质挂在同一网格的不同槽上，`rr3.switch_paint` 切槽号。

## 1. 尾翼 / 轨道配对

### 1.1 问题与根因

原 `rr3lib/parts.py` 的 `aero_parts()` 用 `part_names = sorted(groups)` 配
`for i, tr in enumerate(tracks)`，即**假设"轨道文件顺序 == 部件名字母序"**。

P1（`2014_mclaren_p1`）的两条轨道：

| 轨道 | pivot | 位移 | pitch |
|---|---|---|---|
| track 0 | `(0.000, 0.363, 1.640)` | `(0, 0.296, 0.279)` | **恒 7893（43.36°），不转** |
| track 1 | `(0.000, 0.595, 1.751)` | 同上 | 3931 → −3579（21.59° → −19.66°），**会转** |

字母序是 `WING_REAR` 在前，于是 `WING_REAR` 拿到 track 0（常量），
`WING_STRUT_REAR` 拿到 track 1（会转）——正是用户看到的现象。

### 1.2 判据：网格尾部的 keyframe 表

P1 实测：

```
LOD_A_WING_REAR_mm_ext        _unparsed = 144  → count = 10  （有动画）
LOD_A_WING_STRUT_REAR_mm_ext  _unparsed = 4    → 空表        （不绑动画）
LOD_A_WING_REAR_mm_badges     无 tail
LOD_A_WING_STRUT_REAR_mm_badges 无 tail
```

keyframe 值与 banim 通道的相关性：与 track 0 的所有通道 `corr ≈ 0`，
与 **track 1 的 ch3（pitch）`corr = −0.5677`**。⇒ `WING_REAR` 属于 track 1。

### 1.3 试过但不可靠的判据（别重复试）

| 判据 | 为什么不灵 |
|---|---|
| 质心到 pivot 的距离 | P1 两条轨道 pivot 只差 0.29 m 且都在车尾中线，`WING_REAR` 都是 0.093、`STRUT` 都是 0.217，**完全无法区分** |
| "支架在尾翼下方"的间隙 | 只在 P1 有效；`2014_audi_r8spyder`、`2017_lamborghini_centenario`、`2020_porsche_911_turbo_s`、`2021_lamborghini_countach_lpi`、`2021_lamborghini_sian_fkp_37`、`2021_mercedes_amg_gt_black` 这 6 台会和 keyframe 判据冲突 |
| 最小顶点间距 | P1 NAME 0.0903 m / SWAP 0.0562 m 能分，但 911 两种配对都是 0.0082 m、Battista 是 0.0034/0.0192，没有普适性 |
| banim 的 name table | 44/53 个文件有，但内容全是 `AE_CAR` / `AE_CAR_WHEEL_SPIN` / `AE_CAMERA_*` / `AE_LOOPING` 这类**事件名**，不是部件名 |
| `.points` 里的尾翼锚点 | 不存在。P1 21 条 / 911 17 条 / CX75 19 条，全是 `POINT_WHEEL_*` / `HINGE_*` / `POINT_EXHAUST_*` / `SPLINE_SPECULAR` / `POINT_DRIVER`，**没有任何 WING/AERO/SPOILER** |
| `b.properties` / `b.trailer_words` / `b.footer` | 全空或只是事件表尾 |
| `_animations.xml` | 只有 clip 名和帧范围（P1：`wing_initial 0-0`、`wing_up 0-30`、`pivot_up 30-60`、`pivot_down 60-30`），无部件名 |

### 1.4 实现

`rr3lib/parts.py` 新增三个函数：

`aero_parts()` 的部件名候选改成**三级**（保住 Evija 那种四个独立襟翼）：

```python
roots = [x for x in bases if not any(o != x and x.startswith(o + "_") for o in bases)]
roots.sort()
riders = [x for x in bases if not x.endswith("_BRAKES")]
candidates = [bases, roots, riders]
for cand in candidates:
    if cand and len(cand) == len(tracks):
        part_names = cand
        break
```

1. 全部基名（正常情况）；
2. 只有 roots（把 `WING_REAR_BRAKES` 这类子件折进父件）；
3. 全部基名去掉 `_BRAKES` 乘客（MP4-12C / 675LT / Ford GT 这类车）。

### 1.5 实测结果

- 全库 53 台有 `_wing.banim` 的车：改前 `paired cleanly 48 / warnings 5`，
  改后 **`paired cleanly: 52 warnings: 1 errors: 0`**。
- 唯一剩下的警告是 `2020_mclaren_speedtail` —— 该车 LOD A/B/C **一个 WING 网格都没有**，
  只有 2 条轨道，属数据本身缺失。
- P1 现在正确：`LOD_A_WING_REAR → track 1`、`LOD_A_WING_STRUT_REAR → track 0`。
- 其它车保持名字序不变（回归安全）：CX75、911 Turbo S、R8 Spyder、Regera、
  Veyron SS（4 条）、Chiron（3 条）、Reventon（3 条）、Evija（4 条）全部与改前一致。
- `2017_ford_gt` 改后不再警告：`WING_REAR → t0`、`WING_STRUT → t1`、`WING_STRUT_REAR → t2`。

## 2. 游戏材质与涂装

完整字段级说明、全部实测数字、换算公式都在 **`docs/游戏材质与涂装.md`**。
这里只记实现要点。

### 2.1 三个新模块（纯 Python，无 `bpy`）

| 模块 | 行数 | 干什么 |
|---|---|---|
| `rr3lib/pvr.py` | ~160 | PVR 色带解码（52 字节头、`PVR!` 在偏移 44、像素自 52 起紧排）+ 手写 PNG 导出 |
| `rr3lib/gamematerial.py` | ~480 | 读 `materials.bin` 的 297 块 + 186 条着色器绑定；`Library.shader_for/luts/spec_power/spec_power_top`；`resolve_lut` / `ramp_mean`；`roughness_from_power` / `metallic_from_fresnel` |
| `rr3lib/carmaterial.py` | ~350 | 网格名 → 部件槽 → 材质槽 → 材质名 → 着色器；`car_materials()` 返回每涂装一个 `PaintScheme` |

`rr3lib/__init__.py` 的 `__all__` 加了 `"carmaterial"` / `"gamematerial"` / `"pvr"`（现 23 项）。

### 2.2 关键坑

1. **`shader_blocks()` 必须逐行解析**：`K_UNIFORM` / `K_TEXTURE` 的值是**多行字符串**
   （`"[3]path\n[4]path2"`）。最初当成单条处理，`textures` 只解析出一条、`luts()` 返回 0 个；
   改成 `for line in text.splitlines()` 后 **with LUTs 从 0 → 128**。
2. **查着色器必须用 template 名**：297 个实例按 template 查命中 296，按 instance 名查只有 119。
3. **LUT 路径要插 `.rgb`**：绑定写 `vehicles/shaders/fresnel_gloss.pvr`，
   磁盘上是 `fresnel_gloss.rgb.pvr`。
4. **涂装贴图路径要双路回退**：表里写 `.ptc.pvr.z`、磁盘是 `.dxt.dds.z`，且有的带
   `livery/` 前缀有的不带。只查车目录漏 6925/9971；加 `vehicles/` 根回退后 9248/9971 命中。
5. **贴图节点必须 `extension="REPEAT"`**：P1 的 `misc` 网格 UV 是 `u[-1.04,1.17]`，超出 0..1。

### 2.3 导入器改动（`rr3_blender_addon/__init__.py`）

- 新参数 `materials: str = "simple"`（`simple` / `game`）、`paint: int = -1`。
- `class GameMaterials`：建全部涂装的材质；**参数完全相同的合并**（签名 =
  材质名 + 贴图 + 两条色带 + rough/metal/coat），所以名字是 `<车名>_<材质名>`，
  不同的才带 `P<n>`。
- `_apply_game_materials(objects, car_dir, car, paint)`：每个网格 `me.materials.clear()`
  后 append 全部涂装材质，**并逐个 polygon 设 `poly.material_index`**（Blender 的材质是按
  polygon 分配的，不设就看不到切换）；写 `rr3_paint_slot` / `rr3_paint_slots`。
- `_build_game_material()`：Base Color ← 涂装贴图（`REPEAT`）；Roughness ←
  `sqrt(2/(power+2))`；Metallic ← fresnel 均值线性映射；**Coat** 在
  `power_top >= 200` 时打开；两条色带作为**未连线**的 `ShaderNodeTexImage` 放在
  `NodeFrame` 里（节点名 `ramp_fresnel` / `ramp_specular`）。
- 新 operator `rr3.switch_paint`（*Car ▸ Switch paint scheme*），`paint` 0..63，
  遍历选中对象改 `poly.material_index` 和 `rr3_paint_slot`。注册数 16 → **17**。

### 2.4 实测

- P1：6 套涂装，83 个网格全部 6 槽、83/83 有贴图，场景内 43 个不同材质。
  车身 `LOD_A_BODY_mm_ext` 六槽：`car_paint_gloss`(0.045) / `car_paint_gloss` /
  `car_paint_metallic_cool`(0.447) / `car_paint_metallic_spec_orange` /
  `car_paint_metallic_white` / `car_paint_gloss`，贴图依次
  `_ext_yellow/black/blue/orange/silver/white`。
- LFA：6 套涂装，84 网格 6 槽、70 有贴图，32 个材质。
  `car_paint_metallic_white` → rough 0.447 + **coat 0.045**；`car_paint_gloss` → 0.045 无 coat。
- Huayra：6 套涂装，103 网格 6 槽、85 有贴图。
- `LOD_A_CHASSIS_mm_misc → car_flat`：rough 0.816 / metal 0.000（`fresnel_flat` 全 0 的物证）。
- 无贴图的只有 LFA 的 `chassis`(2) 与 `tyre`(1)：这两个 tag 在涂装表里全库 0 覆盖 / 387 台。
