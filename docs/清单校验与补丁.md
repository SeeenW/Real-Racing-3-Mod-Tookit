# RR3 资源加载 / 清单校验机制 & "加内容不触发下载"补丁

> 结论基于 2026-10-25 在 MuMu（SM-S9210, Android 12）上的实测日志，设备 adb 端口 `127.0.0.1:16384`，
> 游戏包 `com.ea.games.r3_rra`，uid `u0_a44`。

## 1. 加载链路（实测）

```
APK 内 res/raw/res.zip (39,011,304 B, md5 4769452d…, 1611 条目, stored)
        │  每次启动
        ▼
files/apk/res/          ← 引擎解压覆盖（1280 项）
files/apk/checksum.md5  ← 写成 res.zip 的 md5
        │
        ├─ 57 个 asset_list_*.txt 在启动时被逐个 "StartListDownload"
        └─ 每个清单 = `路径 \t md5 \t packedSize \t rawSize`（zlib 打包后的 md5 与大小）
```

- 启动日志样例：
  `CC: AssetManager::StartListDownload() : Downloading asset_list_base.txt`
  `nTotalDownloadBytes = 142212701, nDownloadedBytes = 142212701`
  `*** Asset download skipped - all files up to date!`
- 57 个清单全部 up-to-date 时 **零网络请求**。
- `files/apk/res/asset_list_vehicle_2012_lexus_lfa.txt` 默认 87 行 / 9,264 B / md5 `e3b33a85…`。

## 2. 校验规则（关键）

只要某个清单的**内容**和引擎记住的不一样，就：

1. 计算**这个清单文件自身的 md5**；
2. 请求 `https://firemonkeys.akamaized.net//rr3/live/<清单名>/<md5>.bin`；
3. 停服环境一律 **403**，重试 8 次后 `ASSET DOWNLOAD ERROR!`；
4. 把清单里"本地不存在"的条目当成待下载资源（`assetname: /vehicles/.../xxx.banim`）。

实测两条证据：

| 操作 | 结果 |
|---|---|
| 清单改成 89 行（9,453 B, md5 `107155e0…`），不动其它 | `GET .../asset_list_vehicle_2012_lexus_lfa/107155e064a6ff1c0ace1e0829ca4b84.bin` → 403 |
| 新建 `asset_list_updates.txt`（189 B, md5 `fa6ba3ae…`） | `GET .../asset_list_updates/fa6ba3ae812dbdbabeae737fe1e914a6.bin` → 403 |

**只调换两行顺序、字节数不变、条目全部存在** → 清单 md5 变了（`3369c00b…`）但**不触发下载**（0 次 CDN 请求）。
说明引擎真正关心的是"清单里有没有本地拿不到的条目"，而不是清单 md5 本身。

## 3. 引擎的"记忆"在哪里

`files/.depot/asset_list_base.txtCache.txt`（4,909,607 B, md5 `b4f9b388…`）

- 结构：**13 字节二进制头** `9d f3 f6 a4 | 04 00 00 00 | "7469" | 0a` + 排序好的 `路径\tmd5` 行（47,090 行）。
- 每次启动都会被重写一次（mtime 更新），但**内容不变**（md5 前后一致）。
- 它是 `.depot` 的 md5 注册表：记录了每个资源文件的"打包 md5"。新增条目会被写进去。

> 注意：这个 md5 **不是** 文件原始 md5，也不是 `zlib.compress(raw, level)` 的 md5（试过 level 0–9 × memLevel 1–9 × strategy 0–4 全部不匹配，虽然 packedSize 能对上）。
> 它是引擎自己打包器的产物，我们**无法重算**——但这不影响补丁，因为引擎只拿它判断"本地文件有没有变"。

## 4. 补丁方案（已验证可用）

### 4.1 现象对照

| 场景 | 清单 | 注册表 | 结果 |
|---|---|---|---|
| 原始 | 87 行 | 原始 | 正常，无请求 |
| 只改清单 | 89 行（含 wing 两条） | 原始 | **CDN 403 → 下载错误** |
| 改清单 + 锁 444 | 89 行 | 原始 | 清单不被覆盖，但**仍 403** |
| **改清单 + 锁 444 + 注册表补两条** | 89 行 | **含 wing 两条** | **0 次 CDN、0 错误、游戏正常启动** |

### 4.2 步骤

```powershell
$adb = "D:\Program Files\Netease\MuMu\nx_device\15.0\shell\adb.exe"
$env:ANDROID_ADB_SERVER_PORT="5038"
$S = "-s","127.0.0.1:16384"
$D = "/sdcard/Android/data/com.ea.games.r3_rra/files"

# 1) 生成 89 行清单（原厂 87 行 + 2 条，LF 换行、每行以 / 开头！）
python analysis\make_lfa_list.py re\build\lfa_carlist_89.txt

# 2) 把清单的 md5 写进注册表（新增/更新 `/asset_list_<清单名>` 行）
python analysis\patch_assetlist.py build re\build\lfa_carlist_89.txt `
    re\seed\base_cache2.txt re\seed\base_cache_wing.txt

# 3) 推进设备，清单设 444（世界可读、不可写 → 启动时不被 res.zip 覆盖）
& $adb @S push re\seed\base_cache_wing.txt "$D/.depot/asset_list_base.txtCache.txt"
& $adb @S push re\build\lfa_carlist_89.txt "$D/apk/res/asset_list_vehicle_2012_lexus_lfa.txt"
& $adb @S shell "chown u0_a44:ext_data_rw $D/.depot/asset_list_base.txtCache.txt; chmod 660 $D/.depot/asset_list_base.txtCache.txt; chown u0_a44:ext_data_rw $D/apk/res/asset_list_vehicle_2012_lexus_lfa.txt; chmod 444 $D/apk/res/asset_list_vehicle_2012_lexus_lfa.txt"
```

启动后 `extractAssets` 会报一条 `EACCES`（因为 444 挡住了覆盖），这是**预期行为**，随后
`Assets are added asset_list_vehicle_2012_lexus_lfa.txt` 正常出现，游戏继续。

### 4.3 为什么 444 有效

引擎用 `open(path, O_WRONLY|O_TRUNC)` 解压覆盖；文件是 444 且属主是应用自己时仍然会 EACCES
（Android 的 `extractAssets` 走的是 `AssetManager` 的原生实现，不享受属主写权限的绕过）。
失败后引擎**继续用旧文件**，因此我们塞进去的 89 行清单得以保留。

> 曾试过 `root:root 444`：同样 EACCES，但游戏读取时也会被 SELinux 拦（avc denied），
> **必须让文件属主是 `u0_a44`**。

## 5. 改 res.zip / APK 为什么不可行

- 改设备上的 `files/apk/res.zip`：启动时被 APK 内的 `res/raw/res.zip` 覆盖回 `4769452d…`。
- 改 APK 内的 `res/raw/res.zip`：Python `zipfile` 重建会丢掉 **APK v2 签名块**，
  `pm install -r -d` 直接报
  `INSTALL_PARSE_FAILED_NO_CERTIFICATES: No signature found in package of version 2 or newer`。
  （要做必须用 `apksigner` 重新签名，或自己实现 v2 签名块。）

## 6. 已知限制

- 清单里**每一条都必须指向真实存在的文件**。加一条不存在的条目（`zzz_probe.dat`）会触发
  Cloudcell 下载重试（`assetnotfound`），最终仍失败。
- 新增的 `_wing.banim` / `_animations.xml` 的 md5 列必须与注册表里的值一致（引擎按它判断文件有没有变）。
- 打包 md5 无法重算，所以**新增条目时用原始 md5 也能被接受**（实测 boot12/14 零请求）。
