## 2. 避震行程：已经确证的事实

全部写在 `docs/避震行程-调节范围.md`（400 行，含排查过程），这里只列结论。

### 2.1 滑块 = `[−下拉, +上拉]`，两半来自完全不同的地方

| | 来源 | 怎么算 |
|---|---|---|
| **上拉** | `suspensiondata.nct` 每车 140 B 记录的 **f23/f24**（米） | 写多少就是多少，无 clamp |
| **下拉** | **不存**。引擎用 `f21/f22`（轮胎自由直径）减 `2 ×` 外观块 `f1/f5`（加载半径） | `down = dia − 2 × loaded`，显示时 `int(down × 1000)` |

### 2.2 两次上屏实证

| 车 | dia（f21/f22） | loaded（外观 f1/f5） | 算出来 | 屏幕上 |
|---|---|---|---|---|
| Silvia S15 | 0.634 / 0.639 | 0.312 / 0.312 | `0.00999999` / `0.01499998` | **−9 / −14** |
| Essenza SCV12 | 0.612 / 0.672 | 0.306 / 0.336 | `1.1e-8` / `9e-9` | **0 / 0** |

SCV12 是决定性的一台：加载半径**正好等于自由半径**（赛道胎不压缩），所以下拉是 0、完全不可调；而它的 f23/f24 是 `0.632/0.634`，所以上拉能到 +632 mm。**那个 0.632 不是录入错误。**

### 2.3 为什么以前看着像 "travel − 1"

341 台能对上的车里 **280 台的加载半径就是按 `(dia − travel)/2` 反填的**，两套表数值一致，所以下拉看起来等于 travel。剩下 61 台不一致的（SCV12、保时捷 935、Challenger）才暴露真相。

### 2.4 上拉那半边的显示有个 ±1，**没有解决**

同一串浮点，屏幕读数：

| 写入 travel | float32 | `int()` 会给 | 屏幕 |
|---|---|---|---|
| 0.010 | 0.0099999998 | 9 | **+10** |
| 0.015 | 0.0149999997 | 14 | **+15** |
| 0.180 | 0.1800000072 | 180 | +180 |
| 0.005 | 0.0049999999 | 4 | 前 +5 / 后 +4 |
| 0.025 | 0.0250000004 | 25 | **+24** |

前四次像四舍五入，最后一次是截断，而且那次是唯一一次「值在整数上方却被截掉」。**没有单一规则能拟合这五行**，说明还有第二个变量（最可能是同一次实验里被一起改掉的轮胎直径）。代码里目前的处理是：上拉按 `round()` 报数（所以原厂车报的和屏幕一致），**不保证你输入 25 就一定显示 25**。

要查这个，最省事的实验是：只改 travel、直径不动，看屏幕读数。

### 2.5 f21/f22 不驱动画出来的轮子大小

Silvia 把直径从 0.634 改到 0.649（+15 mm）上屏，用户确认**轮子视觉没有明显变化**。所以「改直径去凑下拉」是安全的，不会把轮子放大。这也是为什么建车流程可以放心用 `f21 = 2×f1 + 下拉`。

## 3. 这次改的代码

### 3.1 `rr3lib/spec.py`（新增 5 个函数）

```python
as_float32(v)                  # 按表的精度取整
display_mm(metres)             # 游戏会打印的整数毫米 = int(f32 × 1000)
diameter_for_down(loaded, m)   # 反解：让下拉显示成 m 的轮胎直径
suspension_range(rec, loaded, up=, down=)     # 一次写两半
suspension_range_mm(rec, loaded)              # 读回 (上拉前, 上拉后, 下拉前, 下拉后)
```

`suspension_range_mm` 的**上拉取 `round()`、下拉取 `int()`**，不是笔误：
下拉是我们解出来让它落在整数上的，上拉是原样存的、游戏打印不一致，取整至少让原厂车报得和屏幕一样。

### 3.2 `rrmod/edit.py`

- `set_suspension_range(root, name, *, up_mm=None, down_mm=None)` —— 主入口。读外观块拿加载半径，写共享表，再走 `sync_file` 更新四本账。
- `set_suspension_travel(...)` 保留成薄封装（只改上拉），组 90 还在测它。

### 3.3 `rrmod/ui/suspui.py`（新文件）

Cars 页 → 详情面板 → **Ride height** 标签页。四个数字框（上拉前/后、下拉前/后），下面一行只读的 "stored: up … tyre … loaded radius …"。

### 3.4 `rrmod/ui/buildui.py`

新增 **`4. Its ride height`** 一节（原来的 4~6 顺延成 5~8），四个框从**捐赠车**预填（修改分支从车本身）。改动时实时显示「轮胎会变成 X m 直径」。
`ride_height()` 总是返回四个数（没改动时写入是 no-op）；`_ride_dirty()` 只用于判断「这次建车算不算有事要做」，不然按钮会一直亮着。

### 3.5 `rrmod/ui/app.py`

两条建车路径都在**轮毂缩放之后**调用 `set_suspension_range`：

- 新车主分支：`install_pack(...)` → 纹理 → 机翼 → **行程** → 数值
- 修改分支：`set_wheel_sizes(...)` → **行程** → 机翼 → 数值

顺序不能反：下拉是量着画出来的轮子算的。

### 3.6 `rrmod/depot.py` / `rrmod/ui/cars.py`

`car_detail` 多返回 `suspension_travel` / `suspension_down`；Overview 多了 `Ride height up` / `Ride height down` 两行。

### 3.7 测试

组 87（行程对）、88（u32 百分比字段）、89（下拉公式）、90（只写上拉）、91（上下两半一起写）。见文末总数。

## 4. 建车流程里那个隐藏 bug（已修）

以前：`car.build_suspension` 把捐赠车的 140 字节记录**整条抄过来，只改前 4 字节的 id**，所以 `f21/f22` 永远是捐赠车的；而 Build 的轮毂缩放只写外观块 `f1/f5`。两边不同步 → 下拉跑偏。

拿 LFA 当捐赠车（`f21 = 712`，自己的 `f1 = 340`，原厂下拉 32 mm）：

| 轮毂缩放 | 写进去的加载半径 | 修之前的下拉 |
|---|---|---|
| ×0.9 | 0.284 | **144 mm** |
| ×1.0（模板 0.2993） | 0.299 | **113 mm** |
| ×1.2 | 0.328 | **56 mm** |

现在建车时四个框从捐赠车预填（32/31 上下），写入时 `dia = 2×f1 + 下拉`，所以建出来的车下拉 = 上拉，和工作室 280 台车的惯例一致。

## 5. 还没做的 / 下一步可以往哪走

按我认为的价值排序：

1. **上拉那 ±1**（§2.4）。做一次「只改 travel、直径不动」的实验就能缩小范围。影响：用户输入 25 可能显示 24，纯显示问题，但会让人不信任这个页。
2. **266 字节外观块里 `+46/+50/+54` 和 `+62/+66/+70` 仍未映射**。`+46` 那组上屏试过 260→520，对下拉零影响；`+62` 那组（7000~10000）跟着车级别走，像弹簧刚度。**下一块该啃的是它们**，方法同这次：找两台同长度块的车对齐 diff，再上屏单变量。
3. **`wheelsize.py` 的 `ARCH_CLEARANCE = 0.035` 是个死常量** —— 注释写着「轮拱回退用的轮唇间隙」，但没有任何代码用它。当初大概想做「按模型轮拱量轮子」，没做完。
4. **`wheelsize.plan(mode="engine")` 用 `f21/2` 当目标半径**，但 Build 对话框没用它（对话框直接用 `mesh × scale`）。两条路算出来的轮子大小不一定一致，值得对齐。
5. **建车对话框没有测试**。这次只做了离屏手测（`BuildDialog(inv)` + 切分支 + 读 `ride_height()`），没进 `test_rrmod.py`。要补的话得先解决构造对话框要扫全库的问题。

## 7. 已知的坑（省得再踩）

| 坑 | 表现 | 解法 |
|---|---|---|
| `python` 是 3.13 | `ModuleNotFoundError: PySide6` | 用 §1.2 那条路径 |
