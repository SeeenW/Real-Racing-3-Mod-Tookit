## 2. 朝向：为什么改成"根空物体转半圈"

`import_driver()` 里现在做三件事，顺序就是用户要求的顺序：

1. `_pose_parts(...)` 按 `.banim` 把 15 个部件摆到各自关节上（`placement="NODE"`，
   每个部件绕自己的原点转，因为它们是绕关节建模的）；
2. 建 `<车名>_DRIVER_ROOT` 空物体，把所有无父对象挂上去；
3. 根空物体 `rotation_mode = "XYZ"`、`rotation_euler = (0, 0, math.pi)`。

代码（`rr3_blender_addon/__init__.py`，`import_driver()` 尾部）：

```python
root = None
if with_root:
    root = bpy.data.objects.new(f"{car}_DRIVER_ROOT" if car else "DRIVER_ROOT", None)
    root.empty_display_type = "PLAIN_AXES"
    root.empty_display_size = 0.3
    root.rotation_mode = "XYZ"
    if root_turn:
        # the .banim is authored with the figure facing -Y; the car's nose is
        # +Y, so the whole rig is turned once, here, instead of mirroring
        # every part (which also swaps the hands and conjugates the rotations)
        root.rotation_euler = (0.0, 0.0, math.pi)
    root["rr3_driver_root"] = True
    root["rr3_root_turn"] = bool(root_turn)
    coll.objects.link(root)
    for ob in objects.values():
        if ob.parent is None:
            ob.parent = root
            ob.matrix_parent_inverse = Matrix.Identity(4)
```

`_anim_matrix()` 的默认参数也从 `flip_driver=True` 改成 `False`。这个函数只保留给"真的想要
一个镜像人偶"的调用方；`import_driver()` 与 operator 都默认不再用它。docstring 里写清了原因：

```
``flip_driver`` mirrors x and y, i.e. turns the figure 180 deg about Z.  It is
**not** needed for the driver: ... Mirroring it puts the head toward the nose
and the legs toward the boot - a driver sitting backwards ...
```

**结果（`tools/smoke_driver.py` 实测）**：5 台车 `chest.y > wheel.y`（胸在方向盘之后）、
头盔 z 大于脚 z、双手到轮缘：

| 车 | 轮缘 r | 左手 / 右手 |
| --- | --- | --- |
| `1951_ferrari_f1_f375` | 0.201 m | 0.164 / 0.175 m |
| `1957_ferrari_500_trc` | 0.186 m | 0.183 / 0.162 m |
| `1962_ferrari_250_gto` | 0.171 m | 0.169 / 0.173 m |
| `2013_caterham_seven_620r` | 0.125 m | 0.103 / 0.126 m |

## 3. 动画选择：读车的 `.bin.nct` 记录

### 3.1 `DriverSelection.dat.nct` 不是动画表

`vehicles/data/DriverSelection.dat.nct`（6,885 B）确实能解（`rr3lib/nct.py` 的 RC4 +
固定 key，`KEY_NCT = A5 35 B3 B1 E8 43 E7 CF`、`DROP_NCT = 133`），但解出来是**F1 车手
选择界面的头像数据**：`"2019 Formula 1 R.S. 19"`、`"DANIEL RICCIARDO"`、
`"quests/f1_2019/drivers/renault/ric.png"`……没有一条动画映射。**别再用它。**

### 3.2 真正的来源：每车自己的数据记录

`vehicles/data/<id>_<车>.bin.nct`（540 个，908–1,457 B）解密后是明文结构，字段按
`u32 长度 + ascii` 存放。其中就有一条 `driver_<x>.banim`：

```
151_2013_caterham_seven_620r.bin.nct（1,055 B）
  ... "2013_CATERHAM_SEVEN_620_R" / "CAR_NAME_SEVEN_620_R" /
      "driver_caterham.banim" / "generic_race"
  driver_caterham.banim 在偏移 890，前一个 u32 = 21（= 字符串长度）
```

全库统计：**224 / 540 条记录有这个字段**，引用**去重后 34 个 `.banim`，全部在
`<depot>/driver/` 磁盘上存在**。没有该字段的 316 台走 `driver.banim`。

**字段值常常猜不到**，这正是要读记录的理由：

| 车 | 记录的答案 | 按车名会猜成 |
| --- | --- | --- |
| `2014_toyota_ts040` | `driver_919_lmp1.banim` | 猜不到 |
| `2014_ferrari_f1_f14t` | `driver_laferrari.banim` | 猜不到 |
| `1971_lamborghini_miurap400sv` | `driver_miura.banim` | 能猜 |
| `2015_ferrari_fxx-k` / `2017_lamborghini_centenario` / `2019_mclaren_senna` | `driver_renault_dezirconcept.banim` | 全猜不到 |
| `2018_bmw_m4_gt4` / `2013_ktm_x_bow_r` | `driver_xbow.banim` | 后者猜不到 |
| `2014_maserati_granturismo_*` / `2020_porsche_911_rsr` / `1990_mercedes_c11` 等 | `driver_granturismo.banim` / `driver_countach.banim` | 多数猜不到 |

### 3.3 新 API（`rr3lib/driver.py`）

| 函数 | 作用 |
| --- | --- |
| `data_dir(depot)` | `<depot>/vehicles/data` |
| `car_record(depot, car)` | 车的 `<id>_<车>.bin.nct`。先精确同名，再取"短的是长的前缀"里最短的那个 —— 覆盖 266/463 台车目录，其余 197 台这个数据包里没有记录 |
| `banim_in_record(nct_path)` | 解密记录后取第一个 `driver*.banim` 字符串 |
| `banim_for(depot, car)` | 三级优先：记录 → 车名包含匹配 → `driver.banim`；返回 `(path, matched)` |

`selftest()` 从 `33 with their own .banim` 变成 **`90 with their own .banim`**（记录能命中的
车目录数）。

### 3.4 operator 参数

`import_scene.rr3_driver` 现在 12 个参数：

| 参数 | 默认 | 说明 |

| `fps` | 30 | |
| `max_frames` | 0 | |
| `placement` | NODE | |
| `root_turn` | **开** | 根空物体绕 Z 转 180° |
| `flip_driver` | **关** | 逐部件镜像（旧默认，已改） |

## 4b. 补修：驾驶员贴图没接到着色器

用户报「导入驾驶员后贴图没有连接到着色器」。根因与修法：

`.m3g` 的材质表里那 15 个部件的材质名就叫 `driver`，所以 `_build_mesh_object()` 在建网格时
**已经**创建了一个名为 `driver` 的材质 —— 按名字哈希出假色、**没有任何贴图节点**。
旧的 `_driver_material()` 走的是"有就复用"的路：

```python
mat = bpy.data.materials.get(DRIVER_MATERIAL)
if mat is None:
    mat = bpy.data.materials.new(DRIVER_MATERIAL)   # ← 几乎永远不会走到
    ...建 BSDF...
if image is not None and mat.node_tree is not None:
    bsdf = mat.node_tree.nodes.get("Principled BSDF")
    tex = next((n for n in ... if n.type == "TEX_IMAGE"), None)
    if tex is None and bsdf is not None:
        tex = ...new...
        mat.node_tree.links.new(...)                # ← 只在新建时连
    if tex is not None:
        tex.image = image                           # ← 复用时只设图片，不连线
```

复用的那个材质里 `bsdf` 是 `nodes.get("Principled BSDF")`（名字对得上，能拿到），
`tex` 是 `None`，于是建节点 + 连线的分支本该执行……但只要该材质在这台 Blender 会话里被
别处（比如先导入过一台车）动过、或者 `TEX_IMAGE` 节点已存在却没连线，
`tex is None` 为假就跳过整段连线，**贴图节点在、线不在**。

现在的 `_driver_material()` 检查的是**成品状态**而不是分支：

```python
def wired_ok():
    for tex in (n for n in nt.nodes if n.type == "TEX_IMAGE"):
        if image is not None and tex.image != image:
            continue
        for link in tex.outputs["Color"].links:
            if (link.to_node.type == "BSDF_PRINCIPLED"
                    and link.to_socket.name == "Base Color"):
                return True
    return False

if not wired_ok():
    nt.nodes.clear()                 # 整棵树重建，不留半成品
    ...Output / Principled / TexImage + 连线 + Roughness 0.6 / Metallic 0 / Specular IOR 0.35...
```

不满足就**清空节点树重建**；满足就原样保留（重复导入幂等，用户改过的参数不被冲掉）。

另外两处也一并加固，因为它们同样会造成"节点树里有贴图、人偶上看不见"：

```python
me.materials.clear()
me.materials.append(mat)
for slot in ob.material_slots:
    slot.link = "DATA"          # 槽挂在对象上时，对象没有覆盖就什么都显示不出来
for poly in me.polygons:
    poly.material_index = 0     # 索引指偏 → 用了别的槽
```

实测（Blender 4.5 headless）：

| 场景 | 结果 |
| --- | --- |
| 全新场景直接导入 | `driver` 材质 = `driver_skin` + `driver.png`(512×512, packed)，`Color → Base Color` 已连 |
| 先导入整车（留下无贴图的 `driver` 材质）再导驾驶员 | 15/15 部件都显示 `driver.png`，`BAD: []` |
| 手工造一个"有贴图节点但没连线"的 `driver` 材质 | 导入后被重建为 `driver.png` 且已连线 |
| `use_nodes = False` 的 `driver` 材质 | 导入后被重建 |
| 连续导入两次（中间手工把 Roughness 改成 0.123） | `0.123` 保留，未重建 |
